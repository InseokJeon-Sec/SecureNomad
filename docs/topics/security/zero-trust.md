# 제로트러스트 (Zero Trust)

## I. 개요
- **정의**: "**절대 신뢰하지 말고 항상 검증하라(Never Trust, Always Verify)**" 를 원칙으로, 네트워크 위치(내부/외부)와 무관하게 **모든 접근 요청을 매번 인증·인가**하는 보안 모델.
- **배경 / 필요성**: 클라우드·원격근무 확산으로 "내부=안전"이라는 **경계 기반(Perimeter) 모델**이 무너졌다. 내부 침투 후 횡적 이동(lateral movement) 공격이 늘며 등장. 美 NIST SP 800-207로 체계화.

## II. 핵심 원칙
| 원칙 | 내용 |
|---|---|
| 명시적 검증 | 사용자·기기·위치·행위 등 모든 신호로 매 요청 검증 |
| 최소 권한 | 꼭 필요한 권한만, 필요한 시간만 (JIT/JEA) |
| 침해 가정 | 이미 뚫렸다고 전제 → 피해 최소화·세분화 |

## III. 구성요소 (ZTA)
```text
요청 → [PEP 정책시행지점] → [PDP 정책결정지점]
         ↑ 신호: 사용자ID · 기기상태 · 위치 · 리스크
         ↓ 허용/차단/추가인증(MFA)
[마이크로 세그멘테이션] 으로 내부를 잘게 분리
```

| 요소 | 역할 |
|---|---|
| PEP (Policy Enforcement Point) | 접근을 실제로 허용/차단 |
| PDP (Policy Decision Point) | 정책에 따라 판단 |
| IAM · MFA | 신원 확인 강화 |
| 마이크로 세그멘테이션 | 횡적 이동 차단 |
| 지속 모니터링 | 행위 기반 이상 탐지 |

## IV. 특징 · 장단점
| 구분 | 내용 |
|---|---|
| 장점 | 내부 위협·횡적 이동 방어, 원격·클라우드 적합, 피해 범위 축소 |
| 단점 | 도입 복잡·비용, 기존 인프라 전환 부담, 과도한 검증 시 UX 저하 |
| 고려사항 | 단계적 도입(핵심 자산부터), ID 체계 선행 |

## V. 비교 — 경계 기반 vs 제로트러스트
| 구분 | 경계 기반 | 제로트러스트 |
|---|---|---|
| 신뢰 | 내부는 신뢰 | 아무도 신뢰 안 함 |
| 검증 | 최초 진입 시 | 매 요청마다 |
| 방어 | 외부 침입 | 내부 확산까지 |
| 전제 | 경계가 안전 | 이미 침해됨 |

## VI. 적용 · 실무 관점
- **ID가 새로운 경계**: IAM·MFA·SSO 정비가 출발점. 이후 기기 신뢰(EDR), 마이크로 세그멘테이션, SASE/ZTNA로 확장.
- MSA·클라우드 환경에서 서비스 간 mTLS, 서비스 메시와 자연스럽게 결합. 관련: [MSA](../software-engineering/msa.md)

## VII. 결론
- 제로트러스트는 제품이 아니라 **전략·아키텍처**다. 한 번에 완성되지 않고 단계적으로 성숙시킨다.
- 핵심은 "위치가 아닌 신원·맥락 기반의 지속 검증".
