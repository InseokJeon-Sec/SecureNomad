## 2.1 핵심 개념 — FM·LLM·생성형 AI

- **파운데이션 모델(FM)**: 방대한 데이터로 **사전학습된 범용 대형 모델**. 하나로 여러 작업에 적응 가능.
- **LLM(대규모 언어 모델)**: 텍스트에 특화된 FM. 다음 토큰을 예측해 문장을 생성.
- **멀티모달 모델**: 텍스트뿐 아니라 이미지·음성 등 여러 양식을 함께 다룸.
- **생성형 AI**: FM을 활용해 새 콘텐츠(글·이미지·코드·요약)를 **생성**.

> 전통 ML은 주로 **예측·분류**, 생성형 AI는 **생성**이 목적이라는 점이 가장 큰 차이.

## 2.2 어떻게 동작하나 — 토큰·임베딩·트랜스포머

- **토큰(Token)**: 텍스트를 쪼갠 처리 단위(단어 조각). 모델은 토큰 단위로 다음 토큰을 **확률적으로** 예측.
- **임베딩(Embedding)**: 토큰·문장을 의미를 담은 **숫자 벡터**로 변환. 의미가 비슷하면 벡터도 가깝다 → 검색·RAG의 기반.
- **트랜스포머(Transformer)**: 현대 LLM의 신경망 구조. **어텐션(attention)** 으로 문맥상 중요한 토큰에 가중치를 둔다.
- **컨텍스트 윈도(Context window)**: 모델이 한 번에 볼 수 있는 토큰 양. 넘치면 잘린다.
- **파라미터(Parameters)**: 모델이 학습으로 조정한 가중치. 많을수록 표현력↑, 비용·지연↑.

## 2.3 FM 수명주기

데이터 선택 → **사전학습(pre-training)** → 적응(파인튜닝/정렬) → 평가 → 배포 → 모니터링.

- **사전학습**: 대규모 범용 데이터로 기초 능력을 만든다(비용이 매우 큼).
- **파인튜닝**: 특정 도메인·말투에 맞게 추가 학습.
- **RLHF(인간 피드백 강화학습)**: 사람 선호로 모델을 정렬(유용·무해하게).

## 2.4 생성형 AI의 가치와 위험

### 장점
- 콘텐츠 생성·요약·번역·코드 작성, 생산성 향상, 빠른 프로토타이핑, 개인화.

### 위험·한계 (시험 단골)

| 위험 | 설명 |
|---|---|
| **환각(Hallucination)** | 그럴듯하지만 **사실이 아닌** 출력 |
| **편향(Bias)** | 학습 데이터의 편향을 그대로 재생산 |
| **비결정성** | 같은 입력에도 매번 다른 답 |
| **프롬프트 인젝션** | 악의적 입력으로 지시를 덮어씀 |
| **지식 한계(cutoff)** | 학습 시점 이후를 모름 → RAG로 보완 |
| **데이터 프라이버시** | 민감정보가 입력·학습에 유입될 위험 |

> 환각·지식 한계는 **RAG**로, 편향·유해성은 **가드레일·책임 AI 도구**로, 비결정성은 **temperature 조절·평가 반복**으로 대응한다.

## 2.5 AWS 생성형 AI 서비스

| 서비스 | 용도 |
|---|---|
| **Amazon Bedrock** | 여러 FM(Anthropic Claude, Amazon Titan/Nova, Meta Llama 등)을 API로. 서버리스, 커스터마이징·RAG·에이전트·가드레일 지원 |
| **Amazon Q Developer** | 코딩·개발 보조 생성형 AI |
| **Amazon Q Business** | 사내 데이터에 연결된 업무용 어시스턴트 |
| **SageMaker JumpStart** | 사전학습 FM을 골라 배포·파인튜닝 |
| **PartyRock** | 코딩 없이 GenAI 앱을 만들어 보는 놀이터(Bedrock 기반) |
| **Amazon Titan / Nova** | AWS 자체 FM(텍스트·임베딩·이미지 등) |

> "파운데이션 모델을 API로 빌려 쓴다" → **Bedrock**. "모델을 직접 고르고 배포·튜닝" → **SageMaker (JumpStart)**.

## 연습문제 (Domain 2)

**Q1.** 방대한 데이터로 사전학습돼 여러 작업에 적응 가능한 범용 대형 모델을 무엇이라 하나?

<details>
<summary>정답·해설</summary>

**파운데이션 모델(FM).** 텍스트 특화 FM이 LLM이다.
</details>

**Q2.** 전통 ML과 생성형 AI의 가장 큰 목적 차이는?

<details>
<summary>정답·해설</summary>

**전통 ML은 예측·분류, 생성형 AI는 새 콘텐츠 생성.**
</details>

**Q3.** LLM이 텍스트를 처리하는 기본 단위는?

<details>
<summary>정답·해설</summary>

**토큰(token).** 모델은 토큰 단위로 다음 토큰을 확률적으로 예측한다.
</details>

**Q4.** 의미가 비슷한 문장일수록 벡터가 가깝게 배치되는, 검색·RAG의 기반이 되는 표현은?

<details>
<summary>정답·해설</summary>

**임베딩(embedding).** 의미를 숫자 벡터로 변환한 것.
</details>

**Q5.** 현대 LLM의 신경망 구조와, 문맥상 중요한 토큰에 가중치를 두는 메커니즘은?

<details>
<summary>정답·해설</summary>

**트랜스포머(Transformer)** 구조와 **어텐션(attention)** 메커니즘.
</details>

**Q6.** 모델이 그럴듯하지만 사실이 아닌 내용을 자신 있게 생성하는 현상은?

<details>
<summary>정답·해설</summary>

**환각(hallucination).** 사실 근거가 필요하면 RAG로 보완한다.
</details>

**Q7.** 모델이 학습 시점 이후의 최신 정보를 모르는 한계를 실무에서 보완하는 방법은?

<details>
<summary>정답·해설</summary>

**RAG(검색 증강 생성).** 외부·최신 지식을 검색해 프롬프트에 붙인다.
</details>

**Q8.** 모델이 한 번에 처리할 수 있는 토큰의 양을 가리키는 용어는?

<details>
<summary>정답·해설</summary>

**컨텍스트 윈도(context window).** 초과분은 잘린다.
</details>

**Q9.** 여러 공급사의 FM을 서버 관리 없이 API로 호출하고 RAG·가드레일·에이전트까지 쓰려 한다.

<details>
<summary>정답·해설</summary>

**Amazon Bedrock.** 완전관리형 FM 플랫폼이다.
</details>

**Q10.** 개발자의 코딩·디버깅을 돕는 AWS 생성형 AI 어시스턴트는?

<details>
<summary>정답·해설</summary>

**Amazon Q Developer.** 업무·사내데이터 어시스턴트는 Q Business.
</details>

**Q11.** 사전학습된 FM을 골라 배포하거나 파인튜닝하는 SageMaker의 기능은?

<details>
<summary>정답·해설</summary>

**SageMaker JumpStart.**
</details>

**Q12.** 사람의 선호 피드백으로 모델을 유용하고 무해하게 정렬하는 기법은?

<details>
<summary>정답·해설</summary>

**RLHF(인간 피드백 기반 강화학습).**
</details>

**Q13.** 같은 프롬프트에도 매번 답이 조금씩 다른 이유와 조절 수단은?

<details>
<summary>정답·해설</summary>

**생성이 확률적(비결정적)이기 때문.** temperature 등 샘플링 파라미터로 다양성을 조절한다(낮으면 일관, 높으면 다양).
</details>

**Q14.** 모델 파라미터 수가 많아지면 일반적으로 어떤 트레이드오프가 생기나?

<details>
<summary>정답·해설</summary>

**표현력·성능은 올라가지만 비용·지연·자원 소모가 커진다.**
</details>

**Q15.** 사전학습과 파인튜닝의 차이는?

<details>
<summary>정답·해설</summary>

**사전학습 = 대규모 범용 데이터로 기초 능력 형성(고비용). 파인튜닝 = 특정 도메인·스타일에 맞춘 추가 학습.**
</details>

**Q16.** 코딩 없이 Bedrock 기반 생성형 AI 앱을 실험해 보는 AWS 놀이터는?

<details>
<summary>정답·해설</summary>

**PartyRock.**
</details>

**Q17.** 생성형 AI 도입 시 데이터 프라이버시 위험을 줄이는 기본 원칙은?

<details>
<summary>정답·해설</summary>

**민감정보를 입력·학습에 넣지 않거나 최소화·마스킹하고, 접근을 통제한다.** 넣지 않은 것은 샐 수 없다.
</details>
