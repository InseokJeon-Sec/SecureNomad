## 1.1 AI / ML / 딥러닝 / 생성형 AI — 포함 관계

큰 원 안에 작은 원이 들어가는 **포함 관계**로 외운다.

- **AI(인공지능)**: 사람의 지능적 작업을 기계가 수행. 가장 큰 범주.
- **ML(머신러닝)**: 규칙을 사람이 코딩하지 않고 **데이터로 학습**해 패턴을 찾는 AI의 한 방식.
- **딥러닝(DL)**: 다층 **신경망**을 쓰는 ML. 이미지·음성·언어 등 비정형 데이터에 강함.
- **생성형 AI(GenAI)**: 딥러닝 기반으로 **새 콘텐츠(텍스트·이미지·코드 등)를 생성**. 파운데이션 모델·LLM이 여기 속함.

> 한 줄: **AI ⊃ ML ⊃ 딥러닝 ⊃ 생성형 AI**. "데이터로 학습"이면 ML, "새 콘텐츠 생성"이면 GenAI.

## 1.2 ML 학습 유형 — 구분이 시험 포인트

| 유형 | 데이터 | 하는 일 | 예 |
|---|---|---|---|
| **지도학습(Supervised)** | **레이블 있음** | 입력→정답 매핑 학습 | 분류(스팸 여부), 회귀(가격 예측) |
| **비지도학습(Unsupervised)** | 레이블 없음 | 숨은 구조 발견 | 군집화(고객 세분화), 이상 탐지, 차원 축소 |
| **강화학습(Reinforcement)** | 보상 신호 | 시행착오로 정책 학습 | 게임, 로보틱스, 추천 최적화 |

- **분류(Classification)** = 범주 예측(스팸/정상), **회귀(Regression)** = 연속값 예측(매출·온도).
- **지도 vs 비지도** 핵심: **레이블(정답)이 있느냐**. "정답 데이터로 학습" → 지도.

## 1.3 ML 개발 수명주기

데이터 수집 → 전처리 → 특성 공학 → 모델 학습 → **평가** → 배포 → 모니터링의 순환이다.

- **학습(Training) vs 추론(Inference)**: 학습=모델을 만드는 과정, 추론=만든 모델로 예측하는 과정.
- **과적합(Overfitting)**: 학습 데이터에만 잘 맞고 새 데이터엔 약함. **과소적합(Underfitting)**: 학습조차 부족.
- **데이터 분할**: 학습(train)/검증(validation)/테스트(test)로 나눠 일반화 성능을 본다.
- **특성(Feature)**: 모델 입력 변수, **레이블(Label)**: 지도학습의 정답.
- **MLOps**: 데이터·모델·배포를 자동화·버전관리·모니터링하는 운영 체계.

## 1.4 AWS AI/ML 서비스 지도 — "무엇을 하는가"로 외운다

### 완성형 AI 서비스 (모델을 직접 안 만든다)

| 서비스 | 용도 |
|---|---|
| **Amazon Rekognition** | 이미지·영상 분석(객체·얼굴·유해 콘텐츠) |
| **Amazon Transcribe** | 음성 → 텍스트(STT) |
| **Amazon Polly** | 텍스트 → 음성(TTS) |
| **Amazon Translate** | 기계 번역 |
| **Amazon Comprehend** | 텍스트 분석(감정·개체·핵심구·PII 탐지) |
| **Amazon Textract** | 문서에서 텍스트·표·양식 추출(OCR+) |
| **Amazon Lex** | 챗봇·음성봇(대화형 인터페이스) |
| **Amazon Personalize** | 개인화 추천 |
| **Amazon Forecast** | 시계열 수요 예측 |
| **Amazon Kendra** | 지능형 엔터프라이즈 검색 |
| **Amazon Fraud Detector** | 온라인 사기 탐지 |

### 플랫폼·생성형 AI

| 서비스 | 용도 |
|---|---|
| **Amazon SageMaker** | ML 모델을 **직접 구축·학습·배포**하는 종합 플랫폼 |
| **Amazon Bedrock** | 여러 **파운데이션 모델**을 API로 쓰는 완전관리형 GenAI 서비스 |
| **Amazon Q** | AWS의 생성형 AI 어시스턴트(Q Developer / Q Business) |

> 구분: **완성형 AI 서비스** = 모델을 가져다 API로 바로 사용. **SageMaker** = 내가 모델을 만든다. **Bedrock** = 파운데이션 모델을 빌려 쓴다.

## 1.5 언제 ML을 쓰나 (그리고 언제 안 쓰나)

- **ML이 맞는 경우**: 규칙이 너무 복잡하거나 수시로 바뀜, 패턴이 데이터에 있음, 대규모·개인화·예측.
- **ML이 과한 경우**: 간단한 결정론적 규칙으로 풀림, 데이터가 없거나 품질이 낮음, 설명가능성이 법적으로 100% 요구되는데 불투명 모델만 가능할 때.
- **비용·정확도·설명가능성·지연** 사이의 트레이드오프를 고려해 선택한다.

## 연습문제 (Domain 1)

먼저 스스로 답을 정한 뒤 해설을 펼쳐 확인한다.

**Q1.** 레이블이 달린 과거 이메일로 "스팸/정상"을 예측하는 모델을 만든다. 어떤 학습 유형인가?

<details>
<summary>정답·해설</summary>

**지도학습(분류).** 정답(레이블)이 있는 데이터로 입력→정답 매핑을 학습한다. 범주 예측이므로 분류.
</details>

**Q2.** 고객을 구매 패턴에 따라 레이블 없이 자동으로 묶으려 한다.

<details>
<summary>정답·해설</summary>

**비지도학습(군집화).** 정답 없이 데이터의 숨은 구조를 찾아 그룹화한다.
</details>

**Q3.** 주택 면적·위치로 **가격(연속값)** 을 예측한다. 분류인가 회귀인가?

<details>
<summary>정답·해설</summary>

**회귀.** 연속적인 수치를 예측하면 회귀, 범주를 예측하면 분류.
</details>

**Q4.** AI·ML·딥러닝·생성형 AI의 포함 관계로 옳은 것은?

<details>
<summary>정답·해설</summary>

**AI ⊃ ML ⊃ 딥러닝 ⊃ 생성형 AI.** 생성형 AI는 딥러닝의 한 응용이다.
</details>

**Q5.** 모델이 학습 데이터에는 매우 정확하지만 새 데이터에서 성능이 크게 떨어진다. 무엇인가?

<details>
<summary>정답·해설</summary>

**과적합(Overfitting).** 일반화 실패다. 더 많은 데이터·정규화·단순한 모델·교차검증으로 완화한다.
</details>

**Q6.** 업로드된 이미지에서 객체와 부적절한 콘텐츠를 탐지하려 한다. 모델을 직접 만들지 않는다.

<details>
<summary>정답·해설</summary>

**Amazon Rekognition.** 이미지·영상 분석 완성형 서비스다.
</details>

**Q7.** 회의 녹음을 텍스트로 바꾸려 한다.

<details>
<summary>정답·해설</summary>

**Amazon Transcribe(STT).** 반대로 텍스트→음성은 Polly.
</details>

**Q8.** 고객 리뷰에서 감정(긍/부정)과 핵심 개체·PII를 추출하려 한다.

<details>
<summary>정답·해설</summary>

**Amazon Comprehend.** 텍스트의 감정·개체·핵심구·PII를 분석한다.
</details>

**Q9.** 스캔한 청구서에서 표와 양식 필드를 구조화해 추출하려 한다.

<details>
<summary>정답·해설</summary>

**Amazon Textract.** 단순 텍스트뿐 아니라 표·양식까지 추출한다(일반 OCR 이상).
</details>

**Q10.** 전자상거래 사이트에 개인화 상품 추천을 넣으려 한다.

<details>
<summary>정답·해설</summary>

**Amazon Personalize.** 개인화 추천 전용 서비스다.
</details>

**Q11.** 과거 판매 데이터로 다음 분기 수요를 예측하려 한다.

<details>
<summary>정답·해설</summary>

**Amazon Forecast.** 시계열 수요 예측 서비스다.
</details>

**Q12.** 내가 직접 데이터로 커스텀 모델을 학습·튜닝·배포하는 전 과정을 관리하려 한다.

<details>
<summary>정답·해설</summary>

**Amazon SageMaker.** 모델을 직접 구축·학습·배포하는 플랫폼이다. 완성형 API 서비스와 구분.
</details>

**Q13.** 여러 공급사의 파운데이션 모델을 서버 관리 없이 API로 호출해 생성형 AI 앱을 만들려 한다.

<details>
<summary>정답·해설</summary>

**Amazon Bedrock.** 완전관리형으로 여러 FM을 API로 제공한다.
</details>

**Q14.** 지도학습에서 '특성(feature)'과 '레이블(label)'의 차이는?

<details>
<summary>정답·해설</summary>

**특성 = 입력 변수, 레이블 = 예측하려는 정답.** 지도학습은 특성으로 레이블을 예측하도록 학습한다.
</details>

**Q15.** '학습(training)'과 '추론(inference)'의 차이는?

<details>
<summary>정답·해설</summary>

**학습 = 모델을 만드는 과정(데이터로 파라미터 조정), 추론 = 완성된 모델로 새 입력에 예측.**
</details>

**Q16.** 어떤 상황이 ML보다 단순 규칙 기반이 더 적절한가?

<details>
<summary>정답·해설</summary>

**규칙이 명확하고 고정적이며 결정론적으로 풀리는 경우.** 예: "금액 ≥ X면 승인 보류" 같은 단순 임계 규칙. ML은 규칙이 복잡·가변적이고 패턴이 데이터에 있을 때 유리하다.
</details>

**Q17.** 강화학습의 핵심 메커니즘은?

<details>
<summary>정답·해설</summary>

**보상(reward) 신호를 통한 시행착오 학습.** 에이전트가 환경과 상호작용하며 누적 보상을 최대화하는 정책을 배운다.
</details>

**Q18.** 데이터를 train/validation/test로 나누는 이유는?

<details>
<summary>정답·해설</summary>

**일반화 성능을 공정하게 측정하기 위해서.** 검증셋으로 튜닝하고, 한 번도 안 본 테스트셋으로 최종 성능을 평가해 과적합을 걸러낸다.
</details>
