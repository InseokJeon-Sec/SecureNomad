# 3대 클라우드 보안 바로 알기 (AWS·Azure·GCP)

> **대상 독자:** 솔루션을 검토·도입하는 담당자. 숫자는 **출처·기준시점**을 함께 표기합니다.

## 1. 공동 책임 모델 (공통)

세 클라우드 모두 같은 원칙입니다.

- **제공자 — OF the cloud** — 데이터센터·하드웨어·네트워크·가상화
- **고객 — IN the cloud** — 데이터·분류·암호화 키, IAM·접근 정책, 설정

> **클라우드 사고의 대부분은 고객 설정 실수**(공개 버킷·과다 권한). 기본이 안전한 게 아닙니다.

## 2. 3사 보안 서비스 비교

| 영역 | AWS | Azure | GCP |
|---|---|---|---|
| IAM | IAM | Entra ID + RBAC | Cloud IAM |
| 네트워크 | VPC·보안그룹 | VNet·NSG | VPC·방화벽 |
| 암호화 키 | KMS | Key Vault | Cloud KMS |
| 위협 탐지 | GuardDuty | Defender for Cloud | Security Command Center |
| 자세 관리(CSPM) | Security Hub | Defender CSPM | SCC |
| 감사 로그 | CloudTrail | Monitor·Activity Log | Cloud Audit Logs |

→ **역할은 같고 이름만 다르다** — 하나를 알면 나머지는 ‘번역’.

## 3. 점유율 · 특징 (Synergy, 2025 Q3)

- **AWS 29%** — 가장 성숙·서비스 방대·레퍼런스 많음
- **Azure(Microsoft) 20%** — MS 생태계·AD·하이브리드·엔터프라이즈
- **Google Cloud 13%** — 데이터·AI·보안 기본값 강함
- 빅3 합산 63%, 분기 $107B 시장.

## 4. 멀티클라우드 도입 실무 — 파악 · 생성 · 결정

**① 파악** — 어느 클라우드·계정 구조, 공동책임 경계, 자산·데이터 소재지, 규제.

**② 생성·준비** — 조직·계정(랜딩존), 중앙 로깅·SIEM, **CSPM/CNAPP 도구**, 키관리·암호화.

**③ 결정** — 네이티브 vs 서드파티, 제로트러스트, 멀티클라우드 통합 관점.

> **멀티클라우드의 함정은 ‘도구 분산’** — CSPM으로 세 클라우드를 한 화면에서 점검.

## 5. 공통 보안 원칙 6

최소 권한 IAM · 저장·전송 암호화 · 전 계정 로깅 · **CSPM 상시 점검** · 제로트러스트 · 자동 대응(탐지→격리·시정).

## 6. 도구 선택

| | 네이티브 | 서드파티 CSPM/CNAPP |
|---|---|---|
| 예 | 각 클라우드 내장 | Wiz · Prisma Cloud · Orca |
| 적합 | 단일 클라우드 | **멀티클라우드(한 화면)** |

## 7. 어떤 클라우드가 어디에

| 상황 | 권장 |
|---|---|
| 범용·스타트업~대기업·방대한 서비스 | AWS |
| MS 생태계·AD·하이브리드 | Azure |
| 데이터·AI·쿠버네티스 | Google Cloud |
| 멀티클라우드 운영 | 통합 CSPM(Wiz·Prisma) |
| 규제·데이터 소재지 민감 | 리전·컴플라이언스 확인 |

## 흔한 오해와 함정

- **클라우드는 기본이 안전** → 설정 책임은 고객(공개 버킷)
- **공동책임 경계 오해** → 데이터·IAM·설정은 늘 고객
- **멀티클라우드인데 도구 분산** → CSPM으로 한 관점
- **IAM 과다 권한** → 루트·관리자 남발이 최대 위험
- **로깅 미설정** → 사고 나도 추적 불가
