# SAC(서버접근제어/PAM) 바로 알기

> **대상 독자:** 솔루션을 검토·도입하는 담당자. 숫자는 **출처·기준시점**을 함께 표기합니다.

## 1. SAC란 — 왜 필요한가

서버에 **공유 root·administrator**로 직접 접속하면 누가 무엇을 했는지 흔적이 없고, 비밀번호가 돌아다니며, 내부자·외주·탈취 계정이 전권을 쥡니다.

**SAC(=PAM, 특권계정관리)** 는 모든 특권 접근을 **게이트웨이**로 모아 인증·승인·기록·통제합니다. 규제(개인정보보호법·전자금융·ISMS)가 접근통제·감사를 사실상 강제합니다.

## 2. PAM 3축

- **접근 통제** — 게이트웨이 경유 강제, 개인 신원+MFA, 직접 접속 차단
- **계정관리(금고)** — 서버 비밀번호를 금고에 보관·자동 교체, **관리자는 비번을 모름**
- **세션·명령 통제** — 전구간 녹화·재생, 위험 명령 차단·승인

## 3. 동작 — 대리 접속

```text
관리자(개인계정+MFA) → 게이트웨이(승인·정책) → 금고(서버 비번으로 대리 접속) → 서버(전구간 기록)
```

핵심은 **관리자가 서버 비밀번호를 모른다** — 금고가 대신 접속하므로 비번 유출·공유가 원천 차단됩니다.

## 4. 도입 실무 — 파악 · 생성 · 결정

**① 파악 (계정 전수조사)**
- 대상 서버 **OS·수량**(Windows/Linux/Unix·클라우드 인스턴스)
- **공유·특권 계정**(root·administrator) 목록
- 서버마다 숨은 **로컬·서비스 계정** 처리 방침
- 접속 경로(SSH·RDP·텔넷·DB), 외주·협력사 접근

**② 생성·준비** — 게이트웨이·이중화, 서버별 **연동 계정**(최소권한), 비밀번호 금고 등록, 개인 관리자 계정, 에이전트/프록시 방식, SIEM 연동.

**③ 결정** — 세션 녹화 범위, 위험 명령 차단, 승인 워크플로, 긴급(break-glass)·예외 접근.

> **공유 root를 없애고 로컬계정까지 빠짐없이 세는 전수조사**가 성패를 가릅니다. (PAM 도입 시 서버 OS·수량·연동계정·로컬계정 처리를 먼저 정하는 것과 같은 성격)

## 5. 비용·시장

- **비용:** 서버(자산) 수 또는 관리자 수 기반. 국내 시스템 접근제어 시장 **~500억 원**, 공공은 **CC인증** 필수. 숨은 비용 = 서버마다 연동 계정·금고 작업, 세션 녹화 스토리지.
- **시장:** 글로벌 PAM 가트너 MQ 리더 **CyberArk · BeyondTrust · Delinea**(2026). 국내: 넷앤드(HIWARE, 조달 1위 주장)·SGA솔루션즈·한싹·피앤피시큐어(DBSAFER AM). 흐름 = 접근제어+계정관리(IAM) 통합, HR 연동 퇴사자 자동 잠금, 클라우드 동적 반영.

## 6. 어떤 환경에 맞나

| 상황 | 권장 |
|---|---|
| 서버·관리자 다수 | SAC 필수 |
| 외주·유지보수 접근 많음 | 게이트웨이+세션 녹화 |
| 금융·공공·개인정보 규제 | CC인증 국산+감사 |
| 클라우드 서버·DevOps | 클라우드 PAM·시크릿 관리 |
| SSH 키·자동화 계정 많음 | 키 관리·시크릿 금고 |

## 흔한 오해와 함정

- **공유 root 계정 유지** → 개인 신원 못 가리면 반쪽
- **세션 녹화만 한다** → 통제 없으면 사후약방문
- **로컬·서비스 계정 누락** → 숨은 계정이 뒷문
- **연동 계정 권한 과다** → 게이트웨이 계정 뚫리면 전권, 최소권한
- **도입=규제 완료** → 정책·기록 점검·대응 운영이 함께
