# ZTNA 바로 알기 — 원리부터 도입·비용·시장까지

> **대상 독자:** 솔루션을 실제로 검토·도입하는 실무 담당자. 원리도 충실히 다루되, "무엇을 준비하고 얼마가 들며 무엇을 고를까"에 무게를 둡니다.
> **숫자 표기 원칙:** 시장·가격 수치는 변동이 크므로 모두 **출처와 기준 시점**을 함께 적었습니다. 계약 견적이 아닌 참고용 범위입니다.

## 1. ZTNA란 무엇인가 — 그리고 왜 생겼나

**ZTNA(Zero Trust Network Access)**는 "네트워크에 들여보낸 뒤 신뢰"하던 기존 방식을 뒤집어, **매 접속마다 사용자·기기·맥락을 검증하고 '그 애플리케이션 하나'에만 접근을 열어주는** 접근 제어 모델입니다. 핵심 원칙은 세 가지입니다.

- **절대 신뢰하지 않고 항상 검증한다** (never trust, always verify)
- **최소 권한** — 필요한 앱 하나만, 네트워크 전체가 아니라
- **접근 후에도 지속 평가** — 세션 중에도 맥락이 바뀌면 끊는다

### 왜 VPN으로는 부족한가

ZTNA는 VPN의 구조적 한계에서 출발했습니다.

| VPN의 문제 | ZTNA의 답 |
|---|---|
| 한 번 접속하면 **내부망 전체**가 보임 (과도한 신뢰) | 앱 단위로만 연결, 나머지는 **보이지도 않음** |
| 계정 탈취 시 **횡적 이동(lateral movement)** 자유 | 앱 격리로 횡적 이동 차단 |
| 기기 상태·위치·시간 등 **맥락 무시** | 접속마다 맥락 기반 정책 평가 |
| 서버 IP·포트가 외부에 노출 | **다크 클라우드** — 인증 전엔 자원이 인터넷에 안 보임 |
| 원격 근무·클라우드 확산에 확장성 한계 | 클라우드 브로커 기반으로 확장 |

코로나 이후 원격 근무와 멀티클라우드가 표준이 되면서, "경계(perimeter)" 자체가 사라졌습니다. 그래서 ZTNA는 제로트러스트 아키텍처의 **가장 먼저 도입되는 실천 수단**이 되었습니다. (제로트러스트의 표준 레퍼런스는 NIST SP 800-207, 구글의 BeyondCorp입니다.)

## 2. 동작 원리와 아키텍처

### 기본 흐름

```text
[사용자/기기]            [ZTNA 브로커(Trust Broker)]          [내부 앱]
     │                         │ (클라우드/게이트웨이)            │
     │ ① 인증 요청 ──────────▶ │                                │
     │   (IdP 연동: SAML/OIDC) │ ② 신원·기기·맥락 검증          │
     │                         │   (MFA, 기기 상태, 위치, 시간)  │
     │                         │ ③ 정책 평가 → 앱 단위 허용      │
     │ ◀──────── 암호화 터널 ──┤ ◀───── 아웃바운드 연결 ────────┤
     │   (그 '앱 하나'에만)    │        (Connector가 먼저 나감)  │
```

핵심은 **커넥터(Connector)가 내부에서 브로커로 '아웃바운드'로 먼저 연결**한다는 점입니다. 그래서 방화벽에 인바운드 포트를 열 필요가 없고, 인증 전에는 자원이 인터넷에서 보이지 않습니다(이것이 VPN과 가장 다른 지점).

### 두 가지 구현 방식 (Gartner 분류)

| 구분 | Endpoint-initiated (에이전트형) | Service-initiated (서비스형) |
|---|---|---|
| 방식 | 단말에 에이전트 설치 | 앱 앞에 커넥터, 단말은 브라우저 |
| 장점 | 기기 상태 점검 정교, 성능 | 에이전트 불가 환경(협력사·BYOD)에 적합 |
| 한계 | 비관리 기기엔 배포 부담 | 웹앱 위주, 기기 신뢰 판단 약함 |
| 흔한 용도 | 임직원 관리 단말 | 외주·파트너·개인기기 |

→ 실무에선 **둘을 섞어** 쓰는 경우가 많습니다. 관리 단말은 에이전트형, 협력사는 클라이언트리스(브라우저)로.

### SDP와의 관계

ZTNA는 **SDP(Software-Defined Perimeter)** 개념을 제품화한 것에 가깝습니다. "인증된 사용자에게만 동적으로 경계를 만들어 준다"는 아이디어가 SDP, 그걸 상용 서비스로 구현한 것이 ZTNA입니다. 국내 벤더는 "ZTNA·SDP"를 함께 표기하는 경우가 많습니다.

## 3. 도입 실무 준비 — 회사가 무엇을 알아야 하나

ZTNA는 "깔면 되는" 제품이 아니라 **사전 조사와 준비가 성패를 가릅니다.** 도입 전에 **① 파악할 것, ② 생성·준비할 것, ③ 결정할 것** 세 묶음을 확정해야 합니다. (PAM 도입 시 서버 OS·수량·연동계정·로컬계정 처리를 먼저 정해야 하는 것과 같은 성격입니다.)

### 3-1. 먼저 '파악'해야 할 것 (현황 조사)

조사가 부실하면 반드시 도입 중반에 막힙니다.

| 대상 | 구체적으로 알아야 하는 것 |
|---|---|
| **애플리케이션** | 앱별 **FQDN/IP, 포트·프로토콜**(웹 HTTP(S)인지 TCP/UDP 앱인지), 내부 **DNS 의존성**, SSO(SAML/OIDC) 지원 여부, 하드코딩된 IP를 쓰는 앱 유무 |
| **사용자·그룹** | IdP의 **그룹·속성 체계**, "어느 그룹이 어느 앱에" 매핑 표, 외부 인력(협력사·외주)의 범위 |
| **기기** | **관리 단말 수량과 OS**(Windows/macOS/Linux/모바일), 비관리·BYOD 규모, 자산 대장 정확도 |
| **네트워크** | 사업장·데이터센터·클라우드(VPC) **구성과 세그먼트**, 아웃바운드 방화벽 정책, 대역폭 |
| **비웹·레거시** | SSH·RDP·DB·파일서버·프린터 등 **씩클라이언트/비웹 앱**, 서버-투-서버 통신, 헬퍼 앱 |

### 3-2. 미리 '생성·준비'해야 할 것

ZTNA를 붙이기 전에 **만들어 두어야 하는 것들**입니다. (PAM의 '연동 계정 생성'에 해당)

- **IdP·MFA 선결** — SAML/OIDC IdP(Okta, Entra ID, 국산 IAM)와 MFA가 먼저 있어야 함. ZTNA의 "검증"은 결국 IdP에 기댑니다.
- **IdP 그룹·조건부 접근 정책** — 앱-그룹 매핑을 담을 그룹 체계, 입·퇴사 프로비저닝(SCIM) 연동.
- **커넥터용 서비스 계정·권한** — 커넥터가 내부 앱에 닿기 위한 전용 계정과 최소 권한. **(PAM의 연동 계정과 같은 개념)**
- **커넥터 배치·이중화** — 데이터센터별·VPC별·세그먼트별로 **몇 대**를 둘지, 이중화·용량 산정, 커넥터의 **아웃바운드 443 허용**.
- **에이전트 배포 체계** — 관리 단말에 에이전트를 뿌릴 수단(MDM·Intune·GPO), 비관리 단말은 **클라이언트리스(브라우저)** 경로 준비.
- **기기 신뢰 신호원** — EDR·MDM 연동으로 기기 상태(패치·디스크 암호화·백신)를 정책 입력값으로.
- **로그 수집 경로** — 접속 로그를 SIEM/SOC로 보내는 연동(보관기간 포함).

### 3-3. '결정'해야 할 정책

- **스플릿 터널링** — 어떤 트래픽을 ZTNA로 보내고 어떤 건 로컬로 둘지.
- **비관리·BYOD 처리** — 차단할지, 클라이언트리스로만 제한할지, RBI(원격 브라우저)로 격리할지.
- **예외 앱 처리** — ZTNA로 못 감싸는 레거시(하드코딩 IP·특수 프로토콜)의 임시 경로.
- **병행 운영·롤백** — VPN과 **공존 기간**, 파일럿 앱 선정, 실패 시 롤백 계획, 사용자 공지·교육.

> **요약:** "무엇을(앱)·누구에게(그룹)·어떤 기기로·어디서(커넥터)" 네 축을 숫자까지 확정해야 도입이 굴러갑니다. 이 조사·준비가 전체 일정의 절반 이상입니다.

## 4. 비용 구조

### 과금 모델

ZTNA는 거의 **사용자당 구독(per-user/월 또는 년)**입니다. 보통 25~100명 **최소 계약**이 붙습니다.

### 참고 가격 (list price, 변동 큼)

| 항목 | 참고가 | 출처 · 기준시점 |
|---|---|---|
| Zscaler ZPA Platform | **US$120/user·년** | Zscaler 리셀러 UK G-Cloud 15 신고가, 2026-01 |
| Zscaler ZPA 단독(엔트리) | **US$60/user·년** | 동일 |
| Zscaler ZPA 클라이언트리스 | **US$86.4/user·년** | 동일 |
| ZTNA/ZPA 월 환산 범위 | **약 US$6~15/user·월** | Jimber SASE 가격 분석, 2026-07 (근사치) |

> 위는 **정가(list) 상한**이며, 실제론 규모 할인·협상가가 적용됩니다. (예: Zscaler는 1,000명 구간에서 단가가 크게 떨어진다는 분석)

### 숨은 비용 (실무에서 자주 빠뜨림)

- **도입·구축(PS) 비용** — 터널·정책 마이그레이션·POP 라우팅. 통합사 공수 약 **US$1,200~1,800/일**, 1년차 오버헤드가 소프트웨어 견적의 **+30~50%**라는 분석.
- **애드온 모듈** — DLP·브라우저 격리·고급 위협탐지는 기본 좌석 위에 별도 과금.
- **갱신 인상(renewal uplift)** — 초기 할인은 앞단에 몰려 있어 **3년차 10~15% 인상**이 흔함 → 계약 시 상한을 박아둘 것.
- **운영 인력** — 정책 튜닝·예외 처리의 지속 공수. (출처: zerotrustcost.com 2026-09, Jimber 2026-07)

## 5. 시장 지형 — 글로벌 vs 국내

### 시장 규모

- **ZTNA 세계 시장:** 2025년 **약 US$19.7억** → 2033년 **약 US$110.3억**, **CAGR 24.2%**(2026~2033). 북미가 2025년 38.1%로 최대, **아시아태평양이 최고 성장(26.2%)**. *(Grand View Research, 기준연도 2025)*
- **도입률:** 글로벌 기업의 **72%가 도입했거나 구축 중**(2022년 44%에서 급증). *(Gartner 조사, 보안뉴스 2026-10-27 인용)*

### 글로벌 벤더 지형

ZTNA는 대개 **SSE/SASE 플랫폼의 한 구성요소**로 팔립니다. 그래서 SSE 평가가 사실상 ZTNA 역량의 바로미터입니다.

- **Gartner SSE 매직 쿼드런트 2025(2025-05-20) 리더:** **Netskope · Palo Alto Networks · Zscaler** (챌린저: Fortinet / 니치: Versa·Broadcom·Cloudflare·iboss·Skyhigh)
- 전용 ZTNA 강자로는 **Zscaler(ZPA)**, 그리고 **Cloudflare·Twingate·Tailscale** 같은 경량·클라우드 네이티브 진영도 부상.

### 국내 지형 (글로벌과 다른 점)

국내는 **글로벌 단일벤더 SASE 플랫폼 재편과 달리, ZTNA를 시작점으로 SWG·CASB·DLP를 점차 연계**하는 흐름입니다. 공공 주도로 확산 중입니다.

- **주요 국산 벤더(2026):** 안랩(XTG), 퓨쳐시스템(ITUz), 모니터랩(아이온클라우드), 소프트캠프(SHIELD), 이니텍(INI-ZTA), 프라이빗에이아이(PacketGo), 지니언스·휴네시온·쿼드마이너 등. *(보안뉴스 2026-10-27)*
- **도입 단계(보안전문가 1,810명 설문, 2026-10):** 개념 검토·교육 **50.8%**, 전략·로드맵 **31.1%**, PoC·시범 **11.5%**, 전사 구축/고도화 각 3.3% → **"실증을 넘어 확산 초기"**.
- **공공 마중물(KISA 제로트러스트 시범사업):** 2024년 약 45억원(4개 컨소) → 2025년 약 42억원(6개) → 2026년 약 35억원(5개)로 **예산 감소 추세**.
- **규제 차이:** 미국(행정명령 14028), EU(NIS2·DORA), 일본(핵심 인프라 가이드라인 준수 의무화)은 **의무화** 흐름인 반면, **국내는 법적 의무화가 없고** 공공은 N2SF로 사실상 요구, 민간은 자발적 동기가 약해 법제화가 수년째 계류.

## 6. 어떤 환경에 ZTNA가 맞나 (의사결정 가이드)

| 상황 | 권장 |
|---|---|
| 원격·하이브리드 근무, SaaS/클라우드 많음 | **ZTNA 우선** — VPN 대체 1순위 |
| 협력사·외주·BYOD에 특정 웹앱만 열어야 함 | **서비스형(클라이언트리스) ZTNA** |
| 관리 단말 중심, 기기 상태 정밀 통제 필요 | **에이전트형 ZTNA + EDR/MDM 연동** |
| 이미 SWG·CASB·방화벽 등 여러 보안이 필요 | **ZTNA 단품보다 SASE/SSE 플랫폼** 검토 |
| 공공·금융 등 규제·망분리 환경 | 국산 벤더 + **단계적 전환**, 망연계와의 정합성 확인 |
| 소규모·엔드포인트 중심 조직(국내 중소) | 엔드포인트 통합형이 현실적 |

## 7. 흔한 오해와 함정

- **"ZTNA = VPN 대체품일 뿐"** → 아닙니다. VPN은 '연결', ZTNA는 '앱 단위 접근 제어 + 지속 검증'. 사고 시 **폭발 반경**이 근본적으로 다릅니다.
- **"깔면 제로트러스트 완성"** → ZTNA는 제로트러스트의 **일부**입니다. 신원(IAM)·기기(EDR)·데이터·거버넌스가 함께 가야 합니다.
- **"IdP 없이 도입"** → 검증의 뿌리가 IdP/MFA입니다. 신원 인프라 없이는 반쪽짜리.
- **"단가만 보고 선택"** → 구축(PS)·애드온·갱신 인상·운영 인력까지 **TCO**로 봐야 합니다(1년차 +30~50%).
- **"한 번에 VPN 제거"** → 현실은 단계적 공존. 파일럿 앱부터 시작하세요.
