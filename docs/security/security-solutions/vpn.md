# VPN 바로 알기 — 원리·한계·전환

> **대상 독자:** 솔루션을 실제로 검토·운영하는 담당자. 숫자는 **출처·기준시점**을 함께 표기합니다.
> **먼저 읽으면 좋은 글:** [ZTNA 바로 알기](./ztna.md) — VPN이 떠난 자리를 대신하는 모델입니다.

## 1. VPN이란 — 두 용도

VPN(Virtual Private Network)은 공용 인터넷 위에 **암호화된 터널**을 뚫어 사설망처럼 쓰는 기술입니다. 용도는 둘입니다.

- **원격 접속 VPN** — 재택·외부 직원이 사내망에 접속. 클라이언트 → 게이트웨이 터널. (오늘의 초점)
- **사이트-투-사이트 VPN** — 지사·데이터센터의 망과 망을 연결. 게이트웨이 ↔ 게이트웨이. (여전히 유효)

핵심 키워드는 **터널**과 **신뢰** — 이 ‘신뢰’가 나중에 문제가 됩니다.

## 2. IPsec vs SSL VPN

| 구분 | IPsec VPN (L3) | SSL/TLS VPN (L4+) |
|---|---|---|
| 방식 | 네트워크 계층 터널 | TLS(443) 기반, 브라우저/클라이언트 |
| 강점 | 사이트 연결·전용 클라이언트 | 어디서나 접속 쉬움 → **원격 접속 주류** |
| 한계 | 방화벽·NAT 통과 설정 복잡 | **인터넷 노출 리스너** = 공격 표면 |

→ 원격 접속의 주류는 SSL VPN이고, 바로 이 **인터넷에 열린 리스너**가 요즘 집중 표적입니다.

## 3. 왜 지금 ‘끝났다’는 말이 나오나 — 구조적 문제

문제는 특정 제품의 버그가 아니라 **구조**입니다.

- **① 인터넷에 열린 리스너** — 게이트웨이가 외부에 노출. 취약점 하나면 **인증 전 침투(RCE)**.
- **② 암묵적 신뢰** — 한 번 접속하면 내부망 전체. 계정 탈취 시 **횡적 이동** 자유. MFA 없으면 비밀번호 하나로 끝.

> **like-for-like 장비 교체는 같은 위험을 반복한다.** 문제는 제품이 아니라 아키텍처입니다.

### 공격 통계

| 수치 | 의미 | 출처·시점 |
|---|---|---|
| **73%** | 검증된 랜섬웨어 침투의 진입점이 레거시 VPN | Coalition Cyber Claims (2025) |
| **22%** | 취약점 악용 침해 중 엣지·VPN 장비 (전년 3%→8배) | Verizon DBIR (2024 데이터) |
| **63%** | 침해 계정에 MFA 미적용 (2022년 22%) | Sophos (2024 데이터) |

## 4. 안전하게 쓰기 — 지금 당장 할 것

한 번에 걷어낼 수 없다면 **위험을 줄이며** 씁니다.

- **MFA 전면 강제** — 비밀번호 하나로 끝나지 않게
- **패치·EoL 점검** — 수명 종료 장비 식별·교체 우선순위
- **노출 최소화** — 관리 인터페이스 외부 차단·허용 IP
- **세그먼트** — 접속 후 닿는 범위를 최소로 분할
- **로깅·탐지** — 비정상 로그인·대량 접근 상시 감시
- **세션 통제** — 유휴 종료·조건부 접근

## 5. 전환 경로 — VPN → ZTNA/SASE

1. **노출 축소** — 관리면 차단·MFA·패치로 급한 불
2. **ZTNA 파일럿** — 핵심 앱부터 앱 단위 접근으로
3. **병행 전환** — VPN과 공존하며 앱 이관
4. **사이트-투-사이트만 잔존** — 원격 접속은 ZTNA/SASE로

> Gartner — 신규 원격접속의 **70%**가 VPN이 아닌 ZTNA (2025년 말 기준 전망).

## 6. 비용·시장

- **비용:** 어플라이언스 + 사용자/대역폭 라이선스. 상대적으로 저렴·성숙하나 **운영 인력(패치·설정)** 상시. 진짜 비용은 **사고** — 랜섬웨어 1건이 수년치 라이선스를 넘긴다.
- **시장:** 전체 VPN 시장 2022년 **$44.6B** → 2030년 **$151.9B**, CAGR 17.7% *(Grand View Research)*. 단, 성장은 **소비자 구독**이 견인하고 **기업 원격접속은 ZTNA/SASE로 이동 중**.

## 7. 어디에 아직 VPN이 맞나

| 상황 | 권장 |
|---|---|
| 지사·DC 간 망 연결 | 사이트-투-사이트 VPN (여전히 적합) |
| OT·폐쇄망·레거시 | VPN 유지(+세그먼트·MFA) |
| 원격 직원·BYOD·SaaS | **ZTNA로 전환** |
| 다지점+보안통합 | SASE 검토 |
| 소규모·예산 제약 | VPN 유지하되 **MFA·패치 필수** |

## 흔한 오해와 함정

- **장비만 새로 사면 안전** → 같은 아키텍처면 같은 위험
- **암호화하니 안전** → 암호화는 도청만 막음, 인증·패치가 방어
- **MFA는 나중에** → 침해 계정 63%가 MFA 미적용, 지금 당장
- **EoL은 급하지 않다** → 수명 종료 장비가 최대 진입점
- **VPN=ZTNA 완전 대체** → 사이트-투-사이트는 남는다, 용도별 공존
