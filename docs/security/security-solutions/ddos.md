# DDoS 방어 바로 알기 — 막는 게 아니라 흡수

> **대상 독자:** 솔루션을 검토·도입하는 담당자. 숫자는 **출처·기준시점**을 함께 표기합니다.

## 1. DDoS란 — 왜 ‘흡수’인가

DDoS(분산 서비스 거부)는 정상 서비스를 거대한 트래픽으로 마비시키는 공격입니다. 핵심은 **막는다기보다 흡수한다** — 받아낼 용량이 있어야 버팁니다.

## 2. 공격 3대 유형

| 유형 | 수법 | 막는 법 |
|---|---|---|
| **볼류메트릭(L3/4)** | UDP·ICMP 플러드, **증폭**(DNS·NTP·memcached) — 대역폭 고갈, 전체 ~78% | 흡수(용량·분산) |
| **프로토콜** | SYN 플러드 등 — 방화벽·LB 세션 테이블 고갈 | 필터 |
| **애플리케이션(L7)** | HTTP 플러드·정교한 봇 — 정상처럼 보여 탐지 어려움 | 행위 분석 |

## 3. 방어 원리

```text
공격+정상 혼재(수 Tbps) → Anycast 분산(전 세계 엣지) → 스크러빙(악성 제거·흡수) → 정상만 원본에
```

핵심은 **용량 + 분산** — AWS·Cloudflare의 거대한 백본이 공격을 나눠 받아 흡수합니다.

## 4. 공격 추세 (2025)

| 수치 | 의미 | 출처 |
|---|---|---|
| **31.4 Tbps** | 2025년 최대 공격(35초·14.1억 pps) | Cloudflare Q4 2025 |
| **47.1M** | 2025 완화 공격 수, 전년 **+121%** | Cloudflare 2025 |
| **78%** | 공격의 L3/4(볼류메트릭) | Cloudflare Q4 2025 |
| **1~4M** | Aisuru 봇넷 감염(IoT·Android TV) | Cloudflare |

## 5. 도입 실무 — 파악 · 생성 · 결정

**① 파악** — 보호 대상(웹/API/네트워크/**DNS**), 공인 IP·대역·회선 용량, **평시 트래픽 베이스라인**(임계치 기준), 지연 민감도.

**② 생성·준비** — **전환 방식(BGP/DNS)**, always-on vs on-demand, **온프렘(즉시)+클라우드(대용량) 하이브리드**, L7 봇 대응(캡차·JS챌린지), 대응 런북·연락 체계.

**③ 결정** — 상시 vs 온디맨드, 탐지 임계치(오탐·미탐 균형), 모의 훈련 주기.

> 공격 시 스크러빙으로 돌리는 **리라우팅을 평시에 테스트**해야 허둥대지 않습니다.

## 6. 비용·시장

- **비용:** 대역폭/요청량 기반 또는 구독. AWS Shield Standard **무료** 기본, Advanced는 대응팀·비용 보호. **종량제는 공격 시 트래픽 폭증 비용** 주의.
- **시장:** 세계 DDoS 방어 **$5.16B(2025) → $20.3B(2033)**, CAGR 18.7% *(Grand View Research)*. 벤더: Cloudflare · Akamai · AWS Shield · Imperva · Radware · NETSCOUT · F5 · A10.

## 7. 어떤 환경에 맞나

| 상황 | 권장 |
|---|---|
| 전자상거래·게임·미디어 | always-on 상시 보호 |
| 금융·공공(표적되기 쉬움) | Shield Advanced급+비용보호 |
| AWS/클라우드 중심 | Shield+WAF+CloudFront |
| 온프렘·네트워크 보호 | 전용 장비+클라우드 하이브리드 |
| 예산 제약·소규모 | CDN 기본 보호+WAF |

## 흔한 오해와 함정

- **방화벽/LB로 막으면 된다** → 대용량은 그걸 먼저 쓰러뜨림, 흡수 용량 필요
- **공격 오면 그때 가입** → 전환·설정에 시간, 평시 준비가 핵심
- **볼류메트릭만 막으면 끝** → L7·봇은 따로 대응
- **종량제면 무조건 싸다** → 공격 시 비용 폭탄 가능
- **DNS는 보호 대상 아니다** → DNS 다운되면 전체 마비
