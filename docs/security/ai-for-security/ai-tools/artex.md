## 개요

ARTEX는 **LLM(대규모 언어 모델) 멀티 에이전트 기반의 자동 침투 테스트 시스템**이다.
사람이 단계마다 지시하지 않아도, 여러 AI 에이전트가 역할을 나눠 정찰·점검 과정을 자율적으로 수행하는 것을 지향한다.

전통적인 펜테스트 도구가 "사람이 도구를 조작"하는 방식이라면, ARTEX 같은 도구는 "AI가 판단하며 진행"하는 방향으로, **침투 테스트 자동화의 흐름**을 보여주는 사례다.

## 특징 (고수준)

- **멀티 에이전트 구조**: 작업을 여러 에이전트가 분담하는 형태로 알려져 있다.
- **플러그형 LLM 백엔드**: 특정 모델에 고정되지 않고, 사용하는 LLM을 바꿀 수 있는 구조다. 보도에 따르면 실제 사례에서는 DeepSeek을 주력으로, GLM·Grok 계열을 보조로 사용한 정황이 확인됐다.
- **오픈소스 기반**: 공개 당시 소스가 오픈되어 있어 누구나 내용을 볼 수 있었다. (현재는 비공개)

:::note
세부 아키텍처·구성·실행 방법은 이 문서의 범위가 아니다. 여기서는 "어떤 성격의 도구인가"까지만 다룬다.
:::

## 데이터 처리 관점 (보안 담당자 체크포인트)

ARTEX의 데이터 처리는 <span className="badge badge--gray">선택 가능</span> 으로 분류했다. 이유는 연결하는 LLM 백엔드에 따라 완전히 달라지기 때문이다.

| 백엔드 선택 | 데이터 흐름 |
|---|---|
| 클라우드 LLM API (예: 외부 상용 모델) | <span className="badge badge--amber">클라우드</span> 입력 데이터가 외부 제공자 서버로 전송됨 |
| 로컬·자체 호스팅 LLM | <span className="badge badge--green">로컬</span> 내 환경 안에서 처리 |

AI 펜테스트 도구를 검토할 때, 대상 시스템 정보·점검 결과가 **외부 LLM으로 전송되는지**를 반드시 확인해야 한다.
클라우드 API를 쓰면 점검 대상의 민감 정보가 제3자에게 넘어갈 수 있다.

## 참고: 알려진 악용 사례

2026년 9월 말~10월 초, ARTEX가 **국내 금융사(신한은행, 예가람저축은행 등) 공격에 악용**되어 데이터가 유출된 정황이 보고됐다.
CrowdStrike가 조사했으며, 노출된 서버에서 ARTEX 설정 파일과 LLM 세션 기록 등이 발견됐다. 공격자는 특정 그룹으로 특정되지 않았고, 중국어 사용·금전 목적으로 추정됐다.

이 사건은 **도구 자체의 문제라기보다 이중용도(dual-use) 도구가 악의적으로 사용된 사례**다.
침투 테스트 도구는 방어자가 쓰면 보안 강화 수단이지만, 공격자가 쓰면 공격 도구가 된다. ARTEX는 그 경계를 잘 보여준다.

### 방어 관점 교훈

- **노출 점검**: 인터넷에 열린 디렉터리·설정 파일·세션 기록이 공격·조사 양쪽의 단서가 됐다. 외부 노출 자산을 주기적으로 점검한다.
- **LLM 트래픽 모니터링**: 내부 서버가 외부 LLM API로 통신하는 이상 트래픽을 탐지한다.
- **유출 후 대응**: 데이터 유출 시 2차 피싱·대출 사기로 이어질 수 있어, 이용자 대상 주의 안내가 필요하다.

## 평가

AI가 침투 테스트를 자율 수행하는 흐름을 보여준 도구다. 방어 관점에서는 "공격자가 이런 자동화를 쓸 수 있다"는 전제를 갖게 하고, 도구 선택 시 **데이터가 외부 LLM으로 나가는지**를 반드시 따져야 함을 상기시킨다.
