# AI를 위한 데이터 엔지니어링

모델은 먹이는 데이터만큼만 좋고, 진지한 AI 시스템 작업 대부분이 모델 상류에 있다. 이 장은 RAG와 파인튜닝 둘 다를 먹이는 **데이터 계층**을 다룬다: 수집, 정제, 중복 제거, PII·거버넌스, 품질 필터링, 그리고 그 모두를 옮기는 파이프라인. RAG 섹션에 있는 건 대부분 팀이 여기 처음 부딪히는 곳이 RAG이기 때문이나, **횡단적**이다: 벡터 스토어용 문서를 준비하는 같은 파이프라인이 파인튜닝용 예시도 준비한다. 데이터 엔지니어링을 "RAG 2단계"로 다루면 과소평가하는 것; 두 소비자가 의존하는 독립 분야다.

## 공유 파이프라인

핵심 아이디어: 하나의 파이프라인, 두 소비자. RAG는 문서를 파싱·정제·중복제거·청킹·강화·임베딩해야. 파인튜닝은 예시를 파싱·정제·중복제거·품질필터·평가셋 대비 오염제거·균형·포맷해야. 처음 다섯 단계가 **공유**; 둘은 꼬리에서만 갈린다.

```
SOURCES        web · docs (PDF/office/email) · DBs/APIs · uploads
   |
[1] DETECT & ROUTE    MIME sniff -> language ID -> route by type
[2] PARSE / EXTRACT   typed elements + structure
[3] CLEAN / NORMALIZE boilerplate strip · encoding repair · unicode · language filter
[4] DEDUP             exact -> MinHash/LSH -> semantic (SemDeDup)
[5] GOVERN            PII detect/redact · license/consent/provenance metadata
[6] QUALITY FILTER    heuristics + model classifier  [always ablate on a downstream eval]
   |-- RAG branch ---------------------|   |-- FINE-TUNE branch ----------------|
   | [7a] chunk -> enrich -> embed     |   | [7b] curate/label -> synthesize    |
   |      -> VECTOR STORE (CDC-fresh)  |   |      -> decontaminate -> balance   |
   |-----------------------------------|   |      -> TRAINING RECORDS           |
CROSS-CUTTING   orchestration (Airflow/Dagster) · lineage (OpenLineage) · versioning (DVC/lakeFS)
```

"대부분의 작업" 프레이밍은 견고: 실무자가 데이터 준비에 시간의 약 80%를 쓴다는 널리 인용되는 어림은 민간전승급(측정이 아니라 여러 출처에 반복)이나 방향은 옳고, AI 에이전트가 이제 준비 시간을 50-70% 줄인다는 벤더 주장은 미검증·자기 이익적. 둘 다 방향으로만 취급.

## 수집

입력은 이기종 더미(PDF, 스캔, 오피스 문서, HTML, 이메일, 이미지). 각 파일이 뭔지 탐지하고 올바른 파서로 라우팅하고 정규화 구조 표현을 내야.

- **확장자가 아니라 내용으로 파일 유형 탐지.** 표준은 `libmagic`(Unix `file` 명령 뒤 라이브러리)의 매직 넘버 스니핑, `python-magic` 같은 바인딩으로 노출. Unstructured 같은 파서가 이렇게 자동 탐지하고 확장자로 폴백.
- 라우팅·필터링용 **언어 탐지**, 흔히 fastText 언어 분류기로.
- **파싱·라우팅.** 콘텐츠 유형이 프로세서 결정: 텍스트 추출 가능 PDF는 빠른 텍스트 경로, 스캔·이미지 PDF는 OCR, 복잡 다단·표 중심 문서는 레이아웃 모델·멀티모달(페이지별 스크린샷) 경로, 오피스 문서는 포맷별 핸들러, 이메일은 헤더·본문 분리. 선도 툴킷은 **Unstructured**(64+ 파일 유형, Title/NarrativeText/Table 같은 타입 요소), **Docling**(IBM, MIT 라이선스, 레이아웃+표 모델, 다중 익스포트, NVIDIA Nemotron Parse 2.0·MinerU 2.5 Pro 같은 플러그형 VLM 백엔드, 2026-09 기준), **MinerU**, **LlamaParse**(멀티모달 에이전트 파스까지 티어 API 모드). 가르칠 점: 발표된 파서 벤치가 불일치하니 리더보드를 믿지 말고 **자신의 문서에서 파서 선택을 벤치마크**.

### 페이지를 작동하는 가장 싼 티어로 라우팅

코퍼스 규모에선 파싱 비용이 최고 리더보드 점수가 아니라 **GPU초당 페이지**로 정해짐. 2026 패턴은 계층: 싼 경로 시도, 품질 검사 실패 페이지만 에스컬레이션.

| 티어 | 예시 | 비용·처리량 | 용도 |
|---|---|---|---|
| 모델 없음 | MinerU 4.0 `flash` 티어, 네이티브 PDF 텍스트 추출 | CPU만 | 디지털 생성 PDF·오피스 파일 |
| 소형 전문 모델 | MinerU `basic`(OCR·수식·표 모델, CPU 가능); NVIDIA Nemotron Parse 2.0(1B 미만, OpenMDW-1.1) | 싸고 자체 호스팅 | 단순 레이아웃 스캔 |
| 파싱 VLM | Cohere Parse `parse-v5.0`(2.3B, 2026-08-27): API로 1,000페이지당 $1.50, GPU 1개 초당 4.5페이지(벤더); jina-ocr-v1(2026-09-14): A100 1개 초당 2.57페이지, CC BY-NC 4.0이라 비상업은 라이선스 없이 | 중간 | 표·폼·다단 |
| 프런티어 VLM | GPT-6 Sol, Claude Opus 5.5, Gemini 3.8 Flash급 | 페이지당 최고 | 어려운 잔여 |

티어 간 정확도 격차가 가격 격차보다 작다: Cohere 자체 ParseBench 실행에서 Cohere Parse가 평균 79.2, GPT-5.5 84.4, Claude Opus 4.8 84.3(둘 다 발표 시 벤더 최신 모델도 아님; 벤더 실행, 의존 전 현 모델로 재실행). MinerU 4.0(2026-09-16)은 티어링 내장(`flash`·`basic`·`standard`·`advanced`), DOCX·PPTX·XLSX·EPUB·HTML을 PDF 변환 없이 네이티브 파싱, 인용을 검증 가능하게 하고 에이전트가 미리 자른 청크 대신 문서를 점진적으로 읽게 하는 안정 블록 로케이터(`doc/tier/page/block`) 반환.

## 정제와 정규화

공유 1차 품질 게이트:
- **보일러플레이트 제거.** 네비게이션·광고·헤더·푸터·쿠키 배너 제거. 대규모 HTML엔 콘텐츠 추출 라이브러리가 표준; FineWeb 프로젝트는 그런 도구로 원시 웹 아카이브에서 추출하는 게 "보일러플레이트를 너무 많이 남긴" 사전 추출 텍스트를 쓰는 것보다 나음을 발견, 즉 미관이 아니라 상류 품질.
- 모지바케·이중 인코딩 텍스트의 **인코딩 수정**, 줄바꿈 정규화.
- 시각적으로 동일한 문자열이 같게 비교되도록 **유니코드 정규화**(NFC/NFKC) — 중복제거·매칭 작동의 전제.
- 신뢰 임계 아래 **언어 필터링**.

가르칠 반직관 단서: **더 많은 필터링이 엄밀히 더 낫지 않다.** FineWeb 어블레이션은 많은 휴리스틱이 낮거나 미미한 영향(이득이 적어 후보 필터 대부분 버림)을 발견, Nemotron-CC(arXiv:2412.02595)는 공격적 휴리스틱 필터링이 자기 품질 분류기가 고품질로 평가한 토큰의 약 18%를 버릴 수 있다고 보고. 필터는 가정이 아니라 다운스트림 평가에 대해 어블레이션해야.

## 중복 제거

중복제거는 최고 레버리지 단계이자 "공유 인프라"의 가장 명확한 사례 — 세 방향으로 값하기 때문. 기초 결과(Lee et al., arXiv:2107.06499)는 학습 데이터 중복제거가 모델이 암기 텍스트를 약 10배 덜 내게 하고, 더 적은 스텝에 동등·더 나은 정확도 도달하며, 결정적으로 **train-test 겹침을 줄여 중복제거가 오염제거이기도** 함을 보고. 반복 PII 암기를 줄여 프라이버시 위험도 완화.

세 티어, 캐스케이드로(싸고 정확한 것 먼저, 비싸고 의미적인 것 나중):
1. **정확**: 전체 문서·정규화 부분문자열 해시. 빠르고 정밀; 축자 복사만 잡음.
2. **퍼지·근중복**: **MinHash + LSH**가 토큰 n-gram 싱글 위 Jaccard 유사도를 추정하고 전쌍 비교를 피하려 후보를 버킷(웹 규모 기본; 일부 벡터 DB가 이제 네이티브 인덱스로). SimHash가 고전 대안. 단서: 이들은 *어휘적*이라 템플릿은 공유하나 의미가 다른 문서가 잘못 제거될 수 있음.
3. **의미·임베딩 중복제거**: **SemDeDup**(arXiv:2303.09540)이 각 항목 임베딩·클러스터링하고 코사인 유사도로 클러스터 내 근중복 버림; 대형 이미지-텍스트 데이터셋의 약 50%를 최소 성능 손실로 제거, MinHash가 놓치는 패러프레이즈 잡음.

프로덕션 패턴은 이들을 조합: MinHash 먼저, 그다음 SemDeDup. 세 방향 보상을 명시: RAG(중복 청크가 문맥 윈도 낭비·다양 증거 밀어냄), 학습(적은 암기, 적은 스텝), 평가 무결성(벤치 대비 중복제거가 오염 방지).

## PII, 동의, 거버넌스

**PII 탐지·수정.** Microsoft Presidio(MIT)가 오픈 표준: NER + 정규식·체크섬·문맥어로 엔티티 탐지하는 Analyzer와 텍스트·이미지(OCR)·구조화 데이터 전반에 수정·대체·마스크·해시·암호화하는 Anonymizer, 코퍼스 규모 배포 가능. 중복제거가 중복 주도 암기를 줄이므로 프라이버시와 중복제거가 연결됨.

**동의·라이선싱·출처**가 이제 위생이 아니라 규제 요건. EU AI Act 하 범용 모델 제공자는 저작권 정책을 유지하고 AI Office 필수 템플릿으로 학습 콘텐츠의 "충분히 상세한 요약"(데이터 출처·저작권 옵트아웃 존중 포함)을 발행해야(이 요약 의무는 2025년 8월부터 신규 범용 모델에 적용, 이미 시장의 모델은 2027년 8월까지). Article 50 투명성 의무는 2026-08-02부터 적용; 그 이전 시장 출시 생성 시스템은 2026-12-02까지 기계 판독 마킹 추가. 파이프라인 거버넌스 함의: 모든 레코드가 수집부터 출처·라이선스·동의 상태·타임스탬프를 메타데이터로 — 바로 리네이지(아래)가 제공하는 것. 거버넌스는 최종 게이트가 아니라 모든 단계에 꿰인 메타데이터. [AI 거버넌스와 컴플라이언스](https://github.com/ombharatiya/ai-system-design-guide/blob/main/13-reliability-and-safety/04-ai-governance-and-compliance.md)(영문) 참고.

**라이선스만이 아니라 획득 방법을 기록하라.** 미국 법원이 *학습*의 합법성과 *획득*의 합법성을 분리 중. Bartz v. Anthropic(2025)에서 법원은 책 학습을 공정 이용으로 판시했으나 해적 복사본으로 라이브러리 구축엔 확장 안 함, 사건은 15억 달러에 합의. 2026년 8월 Sony Music Publishing·Warner Chappell 등 음악 발행사가 가사·악보 담은 책 토렌팅 주장으로 같은 획득 이론에 Anthropic 제소, 미 정부는 The New York Times v. OpenAI에서 OpenAI 학습 공정 이용 입장을 지지하는 브리프 제출(2026-09-02 보도). 파이프라인엔 모든 출처에 **획득 채널**(라이선스 피드, robots 규칙 하 크롤, 구매, 사용자 기여, 토렌트·섀도 라이브러리) 출처 필드 — 오염 출처를 찾아 도려낼 수 있게. 교정 경로는 비쌈: Suno v6(2026-09)가 라이선스 음악으로 재학습, 구 모델 은퇴 선언.

**완전 오픈 릴리스가 출처를 감사 가능하게.** 대부분 오픈 가중치 모델은 가중치만 배포. MBZUAI K2 Horizon 계열(2026-09-03, Apache 2.0, 0.9B~375B-A23B)은 학습 데이터(TxT360-v2 + 사전·중간학습 세트)·학습 코드·중간 체크포인트도 공개해, 모델 카드를 믿는 대신 실제 사전학습 코퍼스 대비 오염 검사 실행 가능.

## 품질 필터링과 강화

**품질 필터링**은 두 계열. **휴리스틱** 규칙(길이, 기호-단어 비, 반복, 불용어 존재)은 싸나 복잡 콘텐츠 노이즈를 못 잡음. **모델 기반 분류기**가 품질·교육 가치 점수; FineWeb-Edu는 LLM 생성 품질 주석에 경량 분류기를 학습해 큰 다운스트림 이득, 훨씬 적은 토큰으로 큰 코퍼스 맞먹음 보고. 플래그 단서: 분류기 필터링은 공짜 점심 아님("데이터 품질 착각" 연구가 오보정 가능 주장)이니 **항상 다운스트림 평가에 필터 어블레이션, 평판으로 믿지 말 것.**

**청킹**(RAG 측 단계)엔 보편 승자 없음: 발표 벤치가 고정 크기·재귀·의미 전략 간 크게 흔들리니 데이터셋 특화이고 기본값이 아니라 평가해야. [청킹 전략](02-chunking-strategies.md) 참고.

**강화와 메타데이터.** 표준 메타데이터(제목·저자·타임스탬프·출처·섹션)와 생성 메타데이터(청크 요약·문맥 접두·청크가 답하는 합성 질문) 첨부 — 단일 축 벡터 유사도를 다차원 필터 검색으로. [문맥 검색](10-contextual-retrieval.md) 참고.

**리네이지.** OpenLineage(참조 구현 Marquez)가 실행·작업·데이터셋 이벤트 추적의 벤더 중립 표준; ML엔 그래프를 피처 테이블·모델·예측으로 전방 확장. 데이터 버전 관리(DVC, lakeFS, Delta/Iceberg 타임트래블)와 함께 거버넌스 메타데이터를 종단 감사 가능하게 하는 기질.

## 파이프라인과 오케스트레이션

**배치 vs 스트리밍.** 사전학습 코퍼스 준비·대량 RAG 인덱싱은 배치 작업(오브젝트 스토리지 위 Spark·Ray). RAG *신선도*는 증분: 출처 문서가 변하면 델타만 재수집. 변경 데이터 캡처(CDC)가 행 수준 출처 변경을 실시간 캡처, RAG엔 "변경·신규·삭제 문서 탐지, 그것만 재파싱·재임베딩, 벡터 스토어에 upsert·delete"로 매핑돼 전체 재인덱스를 피하고 낡거나 고아 벡터 방지.

**오케스트레이터.** Airflow가 가장 큰 생태계의 기본; Dagster가 증분 RAG 재임베딩에 맞는 증분 재계산의 자산 기반; Prefect가 더 가벼운 Pythonic 옵션. Spark·Ray는 오케스트레이터가 스케줄하는 분산 컴퓨트이지 오케스트레이터 자체 아님.

**임베드 단계가 스토어로 이동 중.** MongoDB Atlas Automated Embedding(GA 2026-08-13)이 쓰기 시 신규 문서 임베딩·변경 문서 재임베딩(Voyage 모델); turbopuffer가 2026-09-29 네이티브 임베딩 GA; Elasticsearch `semantic_text`가 수집 시 임베딩. 이는 DAG에서 임베드-upsert 작업을 지우고 CDC 신선도를 DB 문제로. 트레이드오프는 벤더가 이제 모델 버전 소유 — 모델 변경이 계획하는 게 아니라 벤더 스케줄 재임베딩이 됨. 레이크 측은 Milvus 3.0(2026-07)이 Parquet·Iceberg·Lance·Vortex를 읽기 전용 외부 컬렉션으로 제자리 쿼리·온라인 컬럼 백필해, 새 모델로 수억 행 재임베딩이 병렬 인덱스 재구축이 아닌 백그라운드 컬럼 채움이 됨.

**벡터 vs 피처 스토어.** 파이프라인이 끝에서 분기: RAG는 청크 임베딩+메타데이터를 **벡터 스토어**(검색 서빙 계층)에, 파인튜닝은 큐레이션 예시를 시점 정확성의 **피처·학습 레코드 스토어**에. 둘 다 같은 공유 몸통에서 뻗음.

## 파인튜닝용 데이터

RAG에서 갈리는 꼬리:
- **큐레이션이 볼륨을 이긴다.** 신중히 큐레이션된 작은 집합이 흔히 큰 평범한 것을 이김; 품질 삼요소는 난이도·품질·다양성. ("1,000이 10,000을 이긴다" 정확 수치는 예시이지 법칙 아님.)
- **합성 데이터**(교사 모델로 작은 시드에서 Self-Instruct식 확장 후 필터)는 싸게 확장하나 부주의 생성 시 다양성 붕괴·모델 저하 위험이라 다양성이 일급 목표. [합성 데이터 생성](../03-training-and-adaptation/06-synthetic-data-generation.md) 참고.
- **오염제거는 필수.** 플래그 결과(arXiv:2311.04850)는 *재표현·번역된* 테스트 항목이 n-gram 오염제거를 빠져나가고, 그런 데이터로 학습한 모델이 벤치를 프런티어 근처 점수로 과적합할 수 있음을 보고. 프런티어 모델 생성 합성 데이터조차 오염됨. 규칙: n-gram 겹침만이 아니라 임베딩·LLM 매칭으로 오염제거하고 매 평가 전 — 오염이 조용히 점수를 부풀리기 때문. [벤치마크와 리더보드](https://github.com/ombharatiya/ai-system-design-guide/blob/main/14-evaluation-and-observability/03-benchmarks-and-leaderboards.md)(영문) 참고.

## 실패 모드

1. **매직 바이트 탐지 대신 파일 확장자 신뢰**(잘못된 파서, 조용한 쓰레기).
2. **스캔 PDF를 텍스트 전용 경로로 파싱**(빈·부분 추출; 이미지 PDF는 OCR·멀티모달로).
3. **모든 페이지를 가장 비싼 파서로**(티어별 라우팅·실패만 에스컬레이션; 코퍼스 규모엔 페이지당 비용 지배).
4. **사전 제거된 HTML에서 추출**(보일러플레이트 오염; 콘텐츠 추출 도구로 원시에서).
5. **유니코드 정규화 건너뛰기**(정확 중복제거·매칭이 조용히 중복 놓침).
6. **잘못된 티어의 중복제거**(MinHash만으론 패러프레이즈 놓침; 정확→퍼지→의미 캐스케이드).
7. **과공격적 휴리스틱 필터링**(Nemotron-CC 고품질 토큰 약 18% 버림 보고; 모든 필터 어블레이션).
8. **평판으로 품질 분류기 신뢰**(데이터 품질 착각; 다운스트림 검증).
9. **학습 전 PII 미수정**(암기·재생 PII, 중복 시 악화).
10. **라이선스·동의·출처·획득 채널 메타데이터 없음**(감사 불가 코퍼스, 학습 콘텐츠 요약 의무 못 맞추거나 오염 출처 격리 불가).
11. **평가 오염, 조용한 킬러**(n-gram 전용 오염제거가 재표현 항목 놓침; 임베딩·LLM 오염제거).
12. **낡은 RAG 인덱스**(CDC 대신 전체 재인덱스; 비용 폭증, 낡은 답, 고아 벡터).
13. **기본값으로 나쁜 청킹**(벤치 불일치; 데이터셋별 평가).
14. **리네이지 없음**(재현 불가 데이터셋·디버그 불가 회귀; 1일차부터 리네이지 방출).

## 면접 질문

### Q: 중복제거가 AI 데이터 파이프라인에서 가장 중요한 단계 중 하나인 이유는?

**좋은 답변:**
한 연산에서 세 방향으로 값하기 때문. 학습엔 중복제거가 암기를 줄이고(모델이 학습 텍스트를 훨씬 덜 재생) 더 적은 스텝에 동등·더 나은 정확도 도달해 컴퓨트 절약. RAG엔 중복 청크가 문맥 윈도 낭비·다양 증거 밀어내 검색 품질 해침. 결정적으로 벤치 대비 중복제거가 오염제거이기도: 기초 연구가 중복 제거가 평가 점수를 부풀리던 train-test 겹침도 제거함을 발견. 실무상 캐스케이드로: 정확 해시 먼저, 근중복엔 MinHash + LSH, 어휘 방법이 놓치는 패러프레이즈엔 의미 임베딩 중복제거 — 각 티어가 더 싼 것이 못 잡는 걸 잡으니.

### Q: 데이터 오염에 대해 평가 결과를 어떻게 정직하게 유지하나?

**좋은 답변:**
함정은 단순 n-gram 오염제거가 불충분하다는 것. 잘 알려진 결과가 재표현·번역된 테스트 항목이 n-gram 매칭을 바로 빠져나가고 그걸로 학습한 모델이 벤치를 프런티어 근처로 과적합할 수 있으며 강한 모델 생성 합성 데이터조차 오염됐음을 보임. 그래서 문자열 겹침만이 아니라 의미 방법(임베딩 유사도 검색 + LLM 판정자)으로 오염제거하고 매 평가 전 모든 평가셋에 실행. 더 넓게는 가능한 홀드아웃·신규 공개 테스트셋 선호, 모든 벤치를 잠재 오염으로 취급, 중요한 결정엔 자신의 골드 데이터에 기대 — 모델이 안 봤음을 보장할 수 있는 유일한 세트이니.

### Q: RAG용으로 디지털 생성 PDF·스캔·오피스 혼합 500만 페이지를 파싱해야. 비용을 위해 어떻게 설계하나?

**좋은 답변:**
티어별 라우팅하고 GPU초당 페이지를 핵심 지표로. 먼저 내용으로 유형 탐지, 디지털 생성 PDF·오피스 파일을 모델 없는 경로(네이티브 텍스트 추출; MinerU `flash` 티어)로 — 흔히 엔터프라이즈 코퍼스 대부분. 스캔은 작은 자체 호스팅 OCR·레이아웃 모델로. 싼 품질 검사(빈 텍스트, 깨진 표, 낮은 OCR 신뢰, 엉킨 읽기 순서) 실패 페이지만 파싱 VLM으로, 여전히 실패하는 잔여만 프런티어 VLM으로.

산술, 페이지당 약 1,500 입력·800 출력·추론 토큰 없음 가정: Cohere Parse 1,000페이지당 $1.50이면 500만 페이지 $7,500. GPT-6 Sol($2/$10)이 페이지당 약 $0.011, 약 $55,000, Claude Opus 5.5($4/$20)는 사고를 못 끄니 최소 두 배, 반면 전문 파서가 벤더 실행 ParseBench에서 구 프런티어(GPT-5.5, Opus 4.8)보다 약 5점만 뒤짐. 프런티어 계열의 싼 끝이 단순 사다리를 깬다: GPT-6 Luna($0.10/$0.50)가 페이지당 약 $0.0006, 코퍼스 약 $2,750로 파싱 API 아래이니 전문가 옆 벤치에 속함; 열린 질문은 표·스캔에서 버티는지.

전용 GPU가 다시 바꿈: Cohere 보고 GPU당 초당 4.5페이지면 500만 페이지가 약 300 GPU시, Cohere는 50% 활용에서 단일 테넌트 Model Vault 배포가 API를 23% 하회한다 말함(벤더). 자체 호스팅 전 라이선스 확인(jina-ocr-v1은 CC BY-NC), 인용이 페이지·블록 가리키게 블록 수준 로케이터 유지, 라우팅 임계 고정 전 자신의 페이지 수백에 각 티어 벤치마크.
