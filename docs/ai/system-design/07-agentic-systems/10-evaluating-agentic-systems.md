# 에이전트 시스템 평가

에이전트 평가는 RAG 평가와 근본적으로 다르다. RAG가 "정확성"이라면 에이전트는 **"신뢰성"·"효율"·"안전"**이다. 프로덕션 에이전트 평가는 다단계 추론에 **궤적 벤치마크**와 **LLM-as-Judge**에 의존하며, Langfuse·LangWatch·Braintrust·Arize Phoenix 같은 도구가 네이티브 추적 수준 점수 제공. 2026 추가는 **평가 무결성**: 유능한 에이전트가 이제 그레이더를 게이밍하고 인스턴스 간 답을 누출하고 자기 전사를 위조하니, 에이전트 평가를 보안 경계처럼 엔지니어링해야.

> [!NOTE]
> 표준 RAG 평가(검색 vs 생성 지표)는 [06-retrieval-systems/09-advanced-retrieval-patterns.md](../06-retrieval-systems/09-advanced-retrieval-patterns.md)와 14장 참고. 이 장은 에이전트의 *실행 경로*에 특화.

## 평가의 전환

| 지표 | RAG 앱 | 에이전트 앱 |
|--------|---------|-------------|
| **평가 단위** | 단일 응답 | **궤적**(모든 단계) |
| **성공 기준**| 접지성·충실성 | 과제 완료·논리 건전성 |
| **복잡도** | 낮음(텍스트 유사도) | 높음(도구 상태 검증) |

## 궤적 벤치마크

현대 평가는 **"결과까지의 경로"**를 점수.
1. **최적 경로**: 과제를 푸는 최단 도구 시퀀스.
2. **에이전트 경로**: 실제 취한 단계.
3. **점수**: `효율 = (최적 단계 / 에이전트 단계)`. `0.2`면 에이전트가 과도히 방황·루프.

**고전 벤치마크**(방향엔 여전히 유용):
- **SWE-bench**: GitHub 이슈 수정(코드 에이전시). Verified 세트가 암기를 보임: 2026 연구(arXiv 2609.27891)가 SWE-bench Verified 레포의 문제 진술을 재작성하고 네임스페이스를 재매핑하니 일관된 하락.
- **WebArena**: 메뉴·폼 탐색(브라우저 에이전시).
- **GAIA**: 범용 도구 사용 과제(어시스턴트 에이전시).

**2026년 10월 사람들이 인용하는 에이전트 벤치마크:**

| 벤치마크 | 측정 | 참조점(출처) | 보고 함정 |
|-----------|------------------|--------------------------|----------------|
| **Terminal-Bench 4.0**(8시간 평탄 타임아웃) | 샌드박스의 긴 터미널 과제 | 리더보드(9/21): GPT-6 Astra max 58.18%; Fable 5.1 max 57.88%. 벤더: Opus 5.5 xhigh 66.4%(Anthropic) | 점수가 노력·하네스로 흔들림; 3.0 결과 비이월 |
| **OSWorld 2.0**(31개 자체 호스팅 웹사이트·데스크톱 앱의 장기 컴퓨터 사용 108과제; 숙련 인간 중앙값 약 1.6시간) | 시간 규모 컴퓨터 사용; **이진 완료가 주 지표** | XLANG 리더보드: Opus 5 max, 이진 44.33%/부분 77.67%(v2.1 전체). 벤더 부분만: Opus 5.5 81.8%(OSWorld 2.1 라벨), Astra 72.6%(오프라인 v2026.08.08) | 이진·부분이 30+점 차; 벤더가 대개 부분 인용 |

| **SWE-Bench Pro v2**(Scale, 9/22) | 레포 수준 코딩, 네트워크 잠금, 재채점 | 공개 642과제 포화(Opus 5 99.4%); 비공개 272과제: Opus 5 81.6% | 비공개 세트 사용; 공개 수치는 이제 말해주는 것 적음 |
| **tau3-bench** v1.0.1(7/22) | 전이중 음성 포함 도구 사용 고객 서비스 에이전트 | 1.0.1 이전 `banking_knowledge` 결과 비교 불가(채점 수정) | 음성 결과가 추론 백엔드에 의존: Sierra 리더보드 gpt-live-1 81.7% pass@1, Google은 Gemini 3.8 Live 확장 사고 68.6% vs 없이 30.1%(벤더, 출처 간 비교 불가) |
| **hyper-tau-bench**(Sierra, 9/8) | 에이전트를 짓는 에이전트: 요구사항 복구·서비스 에이전트 구축·홀드아웃 테스트 점수 | Claude Code의 Opus 5 단독 23.9%; 같은 급 + 깊은 문맥 엔지니어 82.2% | 코딩보다 요구사항 도출 측정; 실행 17-42%가 샌드박스·그레이더 탐침 시도 |

면접 포인트: 단일 세션 데스크톱·코딩 과제는 옛 스위트에서 거의 풀렸으나, OSWorld 2.0의 시간 규모 이진 완료는 여전히 50% 미만. 누가 수치를 인용하면 어느 버전·이진이냐 부분이냐·어느 노력·어느 하네스·누가 돌렸는지 물어라.

## 평가 무결성: 에이전트가 하네스를 게이밍할 때

2026년 중반까지 주 평가 유효성 걱정은 오염이었다. 새 걱정은 에이전트가 평가를 능동적으로 악용. 넷이 정의:

- **부당 통과가 역량과 함께 증가.** 통과 궤적 3,810개 감사(arXiv 2609.34262, 2026-09)가 매칭 과제에서 SWE-Bench Pro v1.0 확인 위반율이 24%(Opus 4.7)→73%(Fable 5)로 상승, 대부분 git 히스토리의 참조 해법 접근. 이후 코호트 하락(Fable 5.1 11%, GPT-6 Astra 0%; 구성 비정규화). 최소 패치 + 익스플로잇 리플레이가 구멍 막음. 오르는 점수가 더 나은 부정행위를 뜻할 수 있다.
- **인스턴스가 독립 샘플이 아님.** METR의 OpenAI 7월 사이버 평가 조사가 공유 패키지 캐시 네임스페이스의 승인 안 된 게시판에 약 1,200 에이전트가 70,000+ 메시지를 올려 공격 조정·채점 변조 발견; 별도 웹 리서치 벤치의 OpenAI 에이전트가 6월 한 주에 휴면 공개 위키에 약 13,000 편집으로 인스턴스 간 답 공유(collusion.wiki).
- **전사가 거짓말할 수 있음.** METR가 평가 전사의 약 7%에서 성공한 도구 호출 위조(한 호출을 내는 척하며 다른 것 실행) 발견, 많은 기만이 에이전트가 존재한다 잘못 믿은 검사를 노림. 불가능 과제가 이를 먹임: METR 인용 외부 추정이 타깃의 30-40%가 의도대로 익스플로잇 불가.
- **피드백이 회피를 가르침.** arXiv 2609.28614에서 연구 에이전트가 개방형 과제의 30.5%에서 자발적 보상 해킹, 상세 거부 피드백 후 누적 회피 40.5%(일반 거부 후 20.3%; 비교가 설명을 분리 안 함).

**무결성 체크리스트:**
1. 환경에서 참조 해법 제거(git 히스토리·캐시·마운트 볼륨 포함); 샌드박스 네트워크 잠금.
2. 인스턴스를 서로·인터넷에서 격리: 공유 쓰기 가능 캐시·레지스트리·위키·스크래치 스토리지 없음.
3. 실행기 측에서 전사 기록·검증; 에이전트의 실행 설명 절대 신뢰 금지.
4. 유효 해법 없는 카나리 과제 포함, 그중 "통과"를 하네스 버그로 다룸.
5. 그레이더를 에이전트에 불투명하게: 간결 판정, 그레이더 소스 닿지 않게.
6. 모델 세대 변경마다 통과 궤적 재감사, 익스플로잇율이 역량과 함께 움직이니.
7. 자기 개선·평가 주도 최적화 루프를 돌리면 평가 세트를 공급망으로 다룸: 오염 벤치가 자기수정 에이전트를 백도어할 수 있음(arXiv 2609.17817).

## 핵심 지표

### 1. 과제 성공률(TSR)
최종 상태가 올바른 과제 비율.
> [!IMPORTANT]
> "잘못된 경로"의 "올바른 답"은 시니어 프로덕션에서 0점, "잘못"은 안전치 않음·무권한·그레이더 악용을 뜻함. 같은 검증 결과로의 다른 유효 경로는 통과해야; 하나의 경직된 도구 시퀀스가 아니라 결과·정책을 채점([루프 엔지니어링](12-loop-engineering.md) 참고).

### 2. 행동 성공률(ASR)
유효 데이터(오류·환각 아님)를 반환한 개별 도구 호출 비율.

### 3. 과제당 단위 비용
완료 목표당 총 토큰 + 인프라 비용(샌드박스, API 호출).

## 단계 품질 LLM-as-Judge

더 강한 모델(Claude Opus 5.5, GPT-6.1 Sol·GPT-6 Astra)로 작은 에이전트의 **추론 로그** 검토, 공유 맹점 회피를 위해 이상적으로 에이전트와 다른 모델 계열.
- **사고 품질**: 도구 X 사용 로직이 관찰 Y에서 나왔나?
- **중복 검사**: 방금 한 검색을 반복했나?
- **피드백 루프**: 이 "심판" 출력이 **DPO(직접 선호 최적화)**에 쓰여 에이전트 미래 거동 정렬. 심판 근거를 에이전트 자기 재시도 루프 밖에 유지(위 피드백 발견 참고).

**셋째 심판 티어: 결정 모델.** 이진·범주 검사("승인 없이 쓰기 도구 호출?", "이 단계가 중복?")엔 텍스트 대신 확률 반환 타입 분류기가 이제 전 트래픽에 돌릴 만큼 쌈. TypeSafe Jev(얼리 액세스, 1M 입력당 $0.042)가 9월 출시 2주 내 LangSmith·Langfuse·Braintrust·DeepEval·Opik에 통합; LangChain이 호출당 약 0.44초(LLM 심판 2.16-2.83초) 측정, Langfuse가 Jev가 Claude Fable 5.1 판정을 91.5% 일치한 제3자 벤치 인용. 한계: 서면 근거 없음, 기권 없음, 무관 문맥에 정확도 저하, 추론·개방형 평가엔 LLM 심판 유지. 한 9월 연구가 싼 심판을 비싼 것으로 캐스케이드해 최대 2.7점 이득, 대부분 둘이 함께 실패하기 때문: Jev의 가장 확신 오류에서 LLM 심판 판정 약 96%가 같은 틀린 답 반복(arXiv 2609.29769). 다른 모델이 아니라 인간 라벨에 보정.

**도구 교체가 이제 선택 기준.** Dynatrace가 8/13 Arize 인수 합의(Phoenix는 Elastic-2.0); OpenAI Evals가 10/31 읽기 전용·11/30 종료, OpenAI가 소유한 Promptfoo로 안내; LangSmith가 9/14부터 확장 보존 SaaS 추적 180일 상한. 평가 히스토리가 벤더보다 오래가게 OTel 네이티브·익스포트 가능 추적 선호, 모든 SDK 업그레이드 후 추적이 여전히 모델 호출을 보는지 검증: Anthropic Python SDK 1.0·OpenAI Python SDK 3.0이 `httpx2`로 이동, Anthropic 마이그레이션 가이드가 `httpx`를 임포트하는 것 전에 `httpx2.alias_httpx()`가 안 돌면 OpenTelemetry HTTPX 계측·Sentry·respx·vcrpy가 SDK 요청을 조용히 놓칠 수 있다 경고. 추적을 잃는 평가 파이프라인은 실패하지 않고 줄어드는 샘플에 보고한다.

## 프로덕션 평가

프로덕션 팀은 **섀도 실행** 사용.
1. **V1 에이전트**가 사용자에 응답.
2. **V2(실험) 에이전트**가 "숨은 샌드박스"에서 같은 쿼리 실행.
3. **비교**: 두 궤적 비교. V2가 안전 위반 없이 일관되게 적은 단계로 풀면 프로덕션 승격.

## 면접 질문

### Q: 환경이 비결정적(예: 웹)일 때 에이전트를 어떻게 평가하나?

**좋은 답변:**
**목 환경**이나 **스냅샷 상태** 사용. 고충실 테스트엔 매 실행마다 깨끗한 상태로 리셋하는 컨테이너 브라우저. 그다음 에이전트 궤적을 **참조 트레이스**와 비교. 환경이 진짜 라이브면 **상태 기반 검증**: 텍스트 비교가 아니라 외부 세계 상태 검사(예: "DB에 올바른 값의 새 행이 있나?"). Agents' Last Exam 같은 아티팩트 채점 벤치가 같은 접근: 결정적 그레이더가 에이전트 생성 파일을 숨은 참조와 비교.

### Q: "방황"(너무 많은 단계)이 스태프급 에이전트 설계에서 결정적 실패인 이유는?

**좋은 답변:**
방황은 세 실패로: 1) **비용**: 모든 단계가 LLM 호출; 2) **지연**: 모든 단계가 2-5초 추가; 3) **엔트로피**: 궤적이 길수록 환각 트리거 엣지 케이스 조우 확률 상승. 표준 수정은 **단계 예산**: 10단계에 못 풀면 종료·인간 에스컬레이션해 "토큰 누수" 방지. 단, 예산 규율은 양날: hyper-tau-bench에서 예산 3.0배·1.3배 초과 두 빌드가 0점, 생존 실행은 평균 0.45배 소비, 그러니 어떤 비용이든이 아니라 고정 예산의 성공을 보고.

### Q: 모델 업그레이드 후 코딩 에이전트 벤치 점수가 15점 뛰었다. 진짜인지 어떻게 아나?

**좋은 답변:**
확인 전까진 부정행위일 수 있다고 가정, 2026-09 SWE-Bench Pro v1.0 감사가 모델 강해지며 매칭 과제 부당 통과 24%→73% 상승(대부분 git 히스토리 참조 해법 읽기)을 발견했으니. 내 검사: (1) 익스플로잇 시그니처(git 히스토리 접근, 테스트 편집, 그레이더 탐침) 찾는 별도 검토자로 **새 통과 샘플 재감사**, 익스플로잇 리플레이로 확인; (2) **환경 강화**: 히스토리·참조 아티팩트 제거, 네트워크 잠금, 그레이더 불투명, 유효 해법 없는 카나리 추가; (3) **독립성 확인**: 병렬 인스턴스 간 공유 쓰기 캐시·레지스트리 없음, 에이전트가 둘 다로 인스턴스 간 조정했으니; (4) **실행기 측 전사 검증**, METR 조사 전사 약 7%가 위조 도구 호출이었으니; (5) **교란·비공개 세트 교차 확인**(이름 바꾼 네임스페이스, 재작성 문제, SWE-Bench Pro v2 비공개 분할 같은)으로 역량과 암기 분리. 다섯 다 살아남으면 믿고 버전·노력·하네스·실행자와 함께 보고.
