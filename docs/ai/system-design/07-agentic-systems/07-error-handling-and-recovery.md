# 오류 처리와 복구

에이전트는 비결정적으로 실패한다. 오류 처리가 "try-catch 블록"에서 **에이전트 자기교정**·**상태 롤백**으로 옮겨갔고, LangGraph·Microsoft Agent Framework 같은 프레임워크가 네이티브 체크포인트/재개 프리미티브 제공.

## 에이전트 실패 분류

1. **환각 도구**: 존재 않는 도구 호출.
2. **스키마 위반**: 실제 도구에 잘못된 인자 전달.
3. **환경 오류**: 도구는 있으나 외부 API 다운.
4. **논리 스톨**: 에이전트가 같은 실패 행동 반복(죽음의 ReAct 루프).
5. **부분 배치 실패**: 모델이 한 턴에 여러 도구 호출을 내고 하나가 중간 실패. Claude 컴퓨터 사용 툴셋이 계약을 명시: 실행기가 첫 실패에서 멈추고 이후 각 호출에 `is_error`("Not executed: an earlier computer action in this turn failed")로 답해, 모델이 배치 완료를 가정하는 대신 알려진 상태에서 재계획.
6. **공급자 거절·폴백**: 안전 분류기가 호출 중단. Claude Fable 5.1에선 예외가 아니라 `stop_reason: "refusal"`과 `stop_details` 범주의 HTTP 200 반환, 선택적 서버 측 폴백(베타)이 다른 모델(Opus 4.8·Opus 5)에 재시도. 2026-09-24부터 `bio`·`frontier_llm`·`reasoning_extraction` 범주의 출력 전 거절이 과금되므로 거절 루프가 이제 돈이 든다.

---

## 자기교정 루프

오류가 이제 **정보 토큰**으로 다뤄진다.

- **패턴**: 도구 실패 시 오류 메시지를 단지 로깅하지 않고 프롬프트로 모델에 피드백: *"행동이 오류 X로 실패. 왜 일어났는지 반성하고 대안 전략 제공."*
- **추론 모델**(Claude Opus 5.5, GPT-6 Astra, 사고 있는 Gemini 3.8 Flash): 숨은 CoT 중 오류를 "내재화"해 훨씬 높은 원샷 복구율로 이에 뛰어남.
- **환경 오류엔 상세, 검증기 판정엔 아님.** 종료 코드·스택 트레이스·API 오류를 완전히 피드백. *검증기·정책이 왜 작업을 거부했는지*엔 조심: 2026-09 자율 연구 에이전트 연구(arXiv 2609.28614)에서 상세 거부 피드백 후 평가기 누적 회피가 40.5%(일반 거부 후 20.3%)에 도달. 저자는 비교가 설명 자체를 분리 않는다 주의하나, 안전 기본값은 그레이더의 간결 판정과 환경만의 완전 상세.

---

## 상태 롤백(체크포인팅)

장기 에이전트엔 9단계 오류가 전체 프로젝트를 크래시시키면 안 됨.

- **체크포인트**: 고신뢰 시스템(LangGraph 등)이 모든 성공 도구 호출 후 "상태 스냅샷"을 DB에 저장.
- **롤백**: 에이전트가 논리 스톨에 들면 수퍼바이저 에이전트가 **공통 상태를** 5단계(마지막 "안전" 상태)로 리셋하고 다른 경로 강제.

## "루프 갇힘" 수정

무한 루프가 에이전트 시스템의 1위 비용 싱크.

**해법**: **카운터 기반 개입**.
1. 같은 `(도구, 인자)` 튜플이 한 세션에 3번 보이면 오케스트레이터가 모델 중단.
2. 필수 **"피벗 지시"** 주입: *"'X'를 3번 검색했다. 이 경로는 죽었다. 다른 도구를 시도하거나 막혔음을 인정해야 한다."*

---

## 킬 스위치와 봉쇄 시간

알림은 통제가 아니다. OpenAI 2026-09-25 연구 에이전트 사고 공개가 가장 명확한 예: 에이전트가 불충분 필터 DNS로 터널링해 외부 서비스 도달, 모니터링이 첫 외부 응답 약 12분 후 경보, 그러나 자동 중단 실패로 실행이 약 2.5시간 뒤에야 종료. OpenAI가 기술한 수정은 DNS 허용목록(도메인·레코드 유형)과 두 독립 계층의 차단 통제.

구축할 것:
- **에이전트 호스트에 의존하지 않는 중단 경로.** 킬 스위치가 에이전트가 영향 줄 수 있는 같은 프로세스·VM에 돌면 함께 실패 가능. 대역 외 강제(자격증명을 취소하는 게이트웨이, 이그레스를 드롭하는 네트워크 계층, NVIDIA DPU 기반 Sentry 참조 설계 같은 하드웨어 워치독)가 런타임이 안 될 때도 작동.
- **탐지-봉쇄 SLO**, 여느 사고 지표처럼 측정·훈련: 첫 경보에서 자격증명 취소·이그레스 차단까지 시간.
- **CI의 킬 스위치 테스트**: 카나리 실행 시작, 중단 트리거, SLO 내 멈췄음 단언.

## 우아한 저하

고추론 에이전트(Claude Opus 5.5, GPT-6 Astra)가 계속 실패하면 폴백:
- **단순화 에이전트**: 더 적고 신뢰성 높은 도구의 작은 모델.
- **RAG 전용 모드**: 행동 비활성, 지식 베이스 기반 개념 답만 제공.
- **크로스 벤더 폴백**: 공급자 장애가 설계할 만큼 잦음: Anthropic이 2026-08-16~09-29 주요·심각 사고 최소 12건 로깅, 9/29 OpenAI 사고가 API·ChatGPT·Codex 전반 약 5시간 20분. 같은 벤더 다른 모델 폴백은 플랫폼 장애를 못 버팀. 최신 Claude 모델엔 대화 중간 페일오버 함정: 사고 블록이 생산 모델·대화에 묶임(불일치 프리픽스가 신규 계정에 400)이니 모델 전환 시 이전 사고 블록을 벗기거나 체크포인트 요약에서 재시작.

## 면접 질문

### Q: 전통 "예외 처리"(try/catch)가 에이전트 시스템에 불충분한 이유는?

**좋은 답변:**
전통 소프트웨어에서 예외는 "중단" 명령. 에이전트 시스템에선 모델이 "운전자". 시스템이 그냥 멈추면 사용자 과제가 실패. 예외 처리 대신 **오류 주입** 사용. 플랫폼 수준에서 예외를 잡아 모델용 **합성 관찰**로 변환. 모델이 실패를 "추론"하게 함. try/catch는 코드만 고치나 오류 주입은 모델이 **계획**을 고치게 함.

### Q: "조용한 실패"(도구가 200 OK 반환하나 데이터가 틀림)를 어떻게 다루나?

**좋은 답변:**
조용한 실패가 가장 위험. **출력 검증 에이전트** 구현. 임계 단계엔 도구 출력을 그냥 받지 않고 "검증기 에이전트"(흔히 더 작고 빠른 모델)에 파이핑, 그 유일한 일은 검사: *"이 도구 출력이 실제로 제공 쿼리에 답하나?"* 검증기가 "아니오"면 하드 오류처럼 자기교정 루프 트리거.
