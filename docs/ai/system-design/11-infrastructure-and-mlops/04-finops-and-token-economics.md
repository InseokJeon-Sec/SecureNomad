# FinOps와 토큰 경제학

이 장은 대규모 LLM 운영의 **경제학과 규율**이다: AI 지출을 어떻게 모델링·귀속·예산화하고 구조적으로 줄이는가. 추론 내부의 재탕이 아니다. 전술 레버(양자화·배칭·speculative decoding·KV 캐시)는 [비용 최적화 플레이북](../04-inference-optimization/07-cost-optimization-playbook.md)과 [추론 장들](../04-inference-optimization/01-inference-fundamentals.md) 참고.

장 전체를 틀 짓는 앵커 발견, Datadog 2026 State of AI Engineering에서: **시스템 프롬프트가 입력 토큰의 약 69%인데, 호출의 약 28%만 프롬프트 캐싱을 쓴다.** 대부분 프로덕션 스택서 단일 최대·최저 노력 비용 레버가 쓰이지 않고 놓여 있다. AI 제품은 또 제로 한계비용 SaaS가 아니라 매출원가 비즈니스로 돌아, 마진 사고가 이제 엔지니어링 관심사다.

## 비용 모델

가격은 100만 토큰당, 입력 대 출력으로 나뉘어 매겨지고, **출력이 입력보다 상당히 비싸다**(흔히 3-5배, 때로 더). 생성은 autoregressive·컴퓨트 바운드인 반면 입력은 병렬 prefill 패스이기 때문. (현재 모델별 가격은 [가격과 비용](../02-model-landscape/03-pricing-and-costs.md); 빠르게 디플레이트하니 센트가 아니라 *구조*를 모델링.)

모든 요청이 쌓인 지출 계층으로 분해된다. 각각 따로 모델링하는 게 비용을 예측·귀속 가능하게 한다:

| 계층 | 동인 | 거동 | 주 레버 |
|-------|-----------|----------|---------------|
| 시스템 프롬프트/지시 | 고정 스캐폴딩·도구 정의·few-shot | 입력 토큰 약 69%; 비캐시 시 매 호출 지불 | 프롬프트 캐싱 |
| 검색/컨텍스트 토큰 | RAG 청크·주입 문서·장문 | k·청크 크기에 비례; 전부를 압도 가능 | RAG vs 장문; 청크 예산 |
| 대화/메모리 | 채팅 히스토리·에이전트 스크래치패드 | 요약 없으면 무한정 증가 | 윈도잉·요약·컴팩션 |
| 모델 티어 | 프런티어 vs 중 vs 소형·자체 호스팅 | 티어 간 10-100배 스프레드 | 라이트사이징·캐스케이드·라우팅 |
| 출력 길이 | 장황함·형식·max_tokens | 더 높은 출력 요율로 과금 | `max_tokens` 캡·간결 출력 계약 |
| 추론/thinking 토큰 | 확장 thinking 모드 | 출력 요율 과금, 응답엔 안 보임 | 작업 복잡도로 thinking 게이팅 |
| 재시도/오버헤드 | 일시 오류·가드레일 재실행 | 실패 시 배수 | 제한 재시도·서킷 브레이커 |
| 에이전트 멀티스텝 | plan-act-observe 루프·서브에이전트 | 스텝마다 전 스택 배수 | 스텝 상한·실행별 예산 |

**추론 모델과 에이전트가 비용 배수이고, 안 보여서 가장 나쁜 둘이다.** 확장 thinking 토큰은 출력 요율로 과금되나 응답에 안 나타나, "짧은" 호출이 보이는 출력보다 자릿수 더 비쌀 수 있다; 보고 분석은 작업에 따라 배수를 약 3배\~15배로 둔다. thinking은 끄기도 예전보다 어려워: Claude Opus 5.5는 끌 수 없고, Sonnet 5.5 최저 설정도 도구 호출 사이에 thinking을 내보내, reasoning effort가 예산 잡을 노브. 에이전트는 매 스텝 *전체* 토큰 스택을 배수하니, 올바른 측정 단위는 **호출당 비용이 아니라 작업당 비용**. 보고 밴드: 채팅 턴은 센트, 에이전트 멀티스텝 작업은 수십 센트에서 수 달러.

**에이전트는 입력 지배적이라 캐시된 입력 가격이 요금을 정한다.** Anthropic Claude Code 텔레메트리(2026-09-24, 벤더 보고)는 3월\~9월 입력 대 출력 토큰 비가 189:1서 324:1로 상승, 요청당 컨텍스트 2.6배 증가. 그 비율서 출력 가격은 거의 안 중요하고, 캐시 읽기 요율·캐시 적중률이 작업당 비용을 정한다. 하네스가 레버: Anthropic은 하네스 변경이 캐시 미스 입력을 절반 넘게 줄였다 하고, Cursor는 시스템 프롬프트 약 66% 축소·내장 도구를 필요 시만 로드·명시 캐시 중단점 배치로 사용자 토큰 비용 7% 절감 보고(둘 다 벤더 보고).

가르칠 수 있는 요청당 비용 공식:

```
cost = uncached_input × in_rate + cached_input × cache_read_rate + cache_write_tokens × write_rate
       + (output_tokens + reasoning_tokens) × out_rate
cost_per_task = cost_per_request × expected_steps × (1 + retry_rate) + runtime_meters
```

여기서 `runtime_meters`는 토큰이 아니라 시간으로 과금되는 것(호스팅 에이전트 세션·샌드박스·실시간 음성 분)을 커버하고, 모든 요율은 아래의 서비스 티어·레지던시·장문 팩터로 먼저 곱한다.

### 토큰당 요율 너머의 가격 구조

정가는 모델의 끝이 아니라 시작이다. 이 배수들이 이제 실제 요금을 정한다:

| 배수 | 적용처 | 효과 | 설계 대응 |
|------------|------------------|--------|-----------------|
| 장문 절벽 | OpenAI 272K 입력 초과(전체 요청), xAI 200K+ 프롬프트(전 토큰 2배), Gemini 3.1 Pro Preview 200K 초과 | GPT-6 Sol이 100만당 $2/$10서 $4/$15로; 273K 프롬프트가 272K의 약 2배 입력 비용 | 임계 아래 유지하거나 검색으로 대체; Anthropic(Claude 4.6 이상)은 1M까지 평탄 과금 |
| 서비스 티어 | 모든 주요 제공자 | Batch·Flex 0.5배; OpenAI Fast 2배(GPT-5.5서 2.5배)·Ultrafast 6배; Gemini Priority 약 1.8배; Bedrock Priority 1.75배; Opus 5.5 fast 모드 $8/$40 vs $4/$20 | 워크로드 클래스별 티어 정책(아래 배치·비동기 경제학 절) |
| 데이터 레지던시 | Anthropic `inference_geo: "us"`(Claude 4.6 이상 1.1배), OpenAI 레지던시 엔드포인트, Bedrock·Google Cloud 리전 엔드포인트, Mistral EU | 모든 토큰에 약 +10% | 요구 테넌트만 지역 핀 |
| 인트로 가격 | Gemini 3.8 Flash $0.75/$3.75가 2026-12-31까지, 이후 $1.50/$7.50; GPT-5.6 Sol 프로모 $4/$20이 "최소 11/21까지"만 약속(정가 $5/$30) | 프로모 요율 예산은 최대 2배 과소 | 정가로 예측 |
| 과금 거부 | Anthropic: `bio`·`frontier_llm`·`reasoning_extraction`의 출력 전 거부가 2026-09-24부터 과금 | 그 영역 탐침 레드팀·평가가 돈 듦 | `stop_details.category`로 지출 분해 |
| 런타임 미터 | Claude Managed Agents: 실행 세션시당 $0.08 + 토큰, Batch 할인 없음; OpenAI Agents API: 호스팅 샌드박스 컨테이너 요율; gpt-live-1: 세션 분당 $0.05 + 백엔드 토큰 | 토큰 옆 두 번째 미터 | 작업당 비용에 유휴·런타임 거동 모델링 |

## 캐싱: 최상위 비용 레버

바로 앵커 통계 때문에 헤드라인 레버다: 입력 토큰 약 69%인 계층(시스템 프롬프트)이 정적이고 캐싱에 이상적인데 호출의 약 28%만 캐싱. 잠재와 실제의 격차가 가용한 가장 크고 싼 절감.

**제공자 접두사 캐싱**이 접두사 쓰기에 작은 프리미엄, 되읽기에 가파른 할인을 매긴다. 2026년 말 주요 벤더가 읽기를 입력 요율의 약 0.1배로 수렴했고, 최신 모델은 더 낮다:

| 제공자 | 캐시 쓰기 | 캐시 읽기 | TTL·메커니즘 |
|----------|-------------|------------|-------------------|
| OpenAI(GPT-5.6 이상) | 1.25배 입력 | 0.1배(GPT-6.1 Sol서 0.05배) | 1,024 토큰 초과 시 자동; TTL 30분 고정 |
| Anthropic | 1.25배(5분)·2배(1시간) | 0.1배; Opus 5.5서 0.05배; Fable 5.1서 0.025배 | 명시 `cache_control` 중단점 |
| Google(Gemini 3.8 Flash) | 시간당 100만 토큰당 $0.50 저장(인트로; 2027-01-01부터 $1.00) | $0.075 vs $0.75 입력(0.1배, 2026-12-31까지 인트로; 2027-01-01부터 $0.15 vs $1.50) | 캐시 사는 동안 저장 과금 |

읽기 할인이 워낙 깊어 1.25배 쓰기가 첫 적중에 본전, 2배 1시간 쓰기는 두 번째 적중부터 이득(손익분기 약 1.1 읽기). "OpenAI 캐싱은 쓰기 수수료 없이 약 50% 할인"이란 옛 설명은 현 OpenAI 플래그십엔 틀렸다: GPT-5.6 이상이 쓰기 1.25배 과금, 쓰기 수수료 없는 GPT-5.5·GPT-5.4도 읽기 0.1배. 가르칠 때 분명히 할 두 단서: 헤드라인 절감은 **캐시된 접두사에만** 적용되고 전체 요금이 아님, 읽기 요율이 이제 한 벤더 안에서도 4배 차이라 단일 배수가 아니라 모델별 작업당 캐시 비용을 계산.

실제로 잡는 법(규율):
- **프롬프트를 정적→동적 순서로.** 시스템 지시·도구 정의·few-shot을 먼저(안정 접두사), 사용자 쿼리를 마지막. 정확 접두사 매칭이라 앞쪽 변경이 하류 캐시 전체를 무효화.
- **접두사를 안정화.** 캐시 영역에 타임스탬프·요청 ID·호출별 nonce 금지; 도구 정의 순서 핀. 도구가 세션 중간에 나타나야 하면 Anthropic `inline-tools-2026-09-15` 베타가 캐시 접두사 무효화 없이 중간 시스템 메시지로 추가.
- **TTL 경제학 주시.** OpenAI TTL이 30분 고정이라 그보다 드물게 재사용되는 접두사는 안 맞음; Anthropic은 2배 쓰기로 1시간 TTL 구매 가능. 버스티 저재사용 트래픽은 전혀 이득 없을 수도.
- **호출별 캐시 적중률을 일급 지표로 계측.** 프롬프트 재작성·모델 버전 범프·재배열이 조용히 적중률을 떨어뜨림. 두 벤더 다 노출: OpenAI가 프롬프트 캐싱 대시보드(2026-08-20)·Responses API Prompt Cache Diagnostics(9/8 GA), Anthropic 캐시 진단이 9/23 GA.

접두사 캐싱과 별개로 **정확 매치·시맨틱 캐싱**이 반복 *쿼리*에 전체 응답을 서빙. 정확 매치는 리터럴 요청에 키잉(싸고 거짓 양성 0); 시맨틱은 쿼리를 임베딩해 유사 적중에 캐시 응답(자연어 트래픽서 높은 적중률, 거짓 적중 위험은 가드). 레이어링: 정확 매치→시맨틱→접두사, 레이어별 적중률 측정. 개념적으로 [KV 캐시와 컨텍스트 캐싱](../04-inference-optimization/02-kv-cache-and-context-caching.md)의 같은 KV 재사용을 청구 계층서 수익화한 것.

## 배치와 비동기 경제학

OpenAI·Anthropic·Google·Bedrock 모두 **비동기 작업에 약 50% 할인**(입력·출력): 완료 상한 약 24시간의 Batch API, OpenAI·Google·Bedrock은 지연 허용 동기 호출용 Flex 티어도 같은 0.5배. OpenRouter가 2026-09-22 교차 제공자 Batch API 추가(70+ 모델 일반 50% 할인; 베타서 중앙값 7분·90%가 1시간 내 완료 보고). 결정 규칙은 단순: **사람·시스템이 토큰을 기다리지 않으면 언제나 배치.** 고가치 배치 워크로드: 평가·회귀 스위트, 대량 분류·라벨링, 코퍼스 규모 요약·문서 처리, 프롬프트·모델 변경 후 백필, 프롬프트 변형 A/B 테스트. 제품의 오프라인 티어 전체에서 배치 안 하면 약 절반을 테이블에 남긴다.

세 번째 레인은 **프로비전/예약 처리량**(AWS Bedrock Provisioned Throughput 1·6개월 약정, Bedrock Reserved 티어 1·3개월 용량 예약, Azure OpenAI PTU): 사용량과 무관한 시간당 요율의 예약 용량, 지속 워크로드서 약 15-70% 절감 보고, 높고 예측 가능한 활용서만 경제적. Anthropic은 Priority Tier 용량 약정을 더 안 판다(기존 계약은 만기까지), 그래서 보장 Claude 용량은 이제 커스텀 계약·클라우드 예약·우선 티어로. 멘탈 모델은 클라우드 컴퓨트를 거울: 들쭉날쭉·불확실 수요엔 토큰당(배치 포함), 활용이 높고 안정되면 예약 용량.

네 번째 레인은 **속도 지불**: OpenAI Fast(2배; 2026-07-30 Priority서 개명)·Ultrafast(6배; GPT-6 Astra서 9/29 GA), Gemini Priority(약 1.8배), Bedrock Priority(1.75배), Claude fast 모드(리서치 프리뷰, Claude API만). 한 모델이 이제 티어만으로 12배 가격 범위(0.5배\~6배)를 걸칠 수 있어, 비용 모델엔 워크로드 클래스별 티어 정책이 필요:

| 워크로드 | 누가 기다리나 | 티어 |
|----------|----------------|------|
| 평가·백필·대량 라벨링 | 아무도 | Batch(0.5배) |
| 백그라운드 에이전트·비동기 보강 | 시스템; 분은 괜찮음 | 제공되는 곳의 Flex(0.5배) |
| 채팅·대화형 에이전트 | 사람; 초 | 표준 |
| 음성·하드 지연 SLO | 사람; 1초 미만 | Fast·Priority(1.75-2배); 측정된 SLO가 지불되는 곳만 Ultrafast(6배) |

## FinOps 규율

FinOps Foundation의 프레이밍: **추론이 많은 배포서 총 GenAI 지출의 80-90%**라, 규율은 학습이 아니라 요청당 추론 경제학에 중심. 운영 핵심:

- **귀속.** 모든 호출을 팀·기능·고객/테넌트·모델·경로·환경으로 태그. 기술 인에이블러는 API 앞의 토큰 프록시·[게이트웨이](03-ai-gateways-and-model-routing.md)로 각 호출 출처 식별. 귀속 없으면 단위 경제학 계산·어느 유스케이스가 비용을 버는지 볼 방법이 없음.
- **차지백 전 쇼백.** 가시성 대시보드(제공자·모델·팀·테넌트별, 일 예측·스파이크 알림)로 시작, 태그가 신뢰되면 팀 청구로 승급.
- **단위 경제학.** 사용자당·대화당·해결 티켓/케이스당 비용, 매출·총마진 대비 AI 비용 추적. AI 제품을 매출원가 비즈니스로 가르쳐라.
- **마진 현실.** 보고 스냅샷은 AI 제품 총마진을 전통 SaaS의 80-90%보다 약 25-30포인트 아래로 둔다, 요청마다 가변 토큰 비용이 있어서. 그래서 **성과 기반 가격**(해결 티켓당·완료 작업당)이 부상, 해결 지원 티켓당 고정가 같은 앵커 보고. 과제: 해결당 가격 매기기 전에 해결당 비용을 알라.
- **fail-closed 예산.** 제공자 캡은 무딘 도구. Anthropic 사용 티어(Start·Build·Scale)에 월 지출 캡 $500·$1,000·$200,000; 걸리면 다음 달 1일 00:00 UTC까지 조직 전체에 `enforced_spend_limit_reached` HTTP 429·`retry-after` 없음. Claude Managed Agents 세션 예산(2026-08-07)은 개별 세션을 `budget_reached`로 일시정지, 원하는 입도. 자체 기능별·세션별 예산을 제공자 캡 훨씬 아래로 설정해, 폭주 기능이 모든 제품의 제공자 컷오프 대신 내 알림을 울리게.
- **툴링.** 게이트웨이가 실시간 요청별 제어·지출 캡, FinOps 플랫폼(Helicone·Vantage·Finout·Amnic·클라우드 비용 도구)이 교차 클라우드 할당·차지백. 성숙 스택은 둘 다. 표준화 전 도구 현 상태 확인; 이 카테고리는 churn하니(예: Helicone이 2026-03 Mintlify에 인수), 비용 데이터를 자체 웨어하우스에 내보내기 가능하게 유지.

## 구조적 비용 결정

이 아키텍처 수준 선택이 비용을 2-50배 움직인다, 호출별 튜닝 너머:

- **라이트사이징·캐스케이드·라우팅.** 품질 기준을 넘는 최저가 모델로 라우팅, 저신뢰에만 에스컬레이트. 약 95% 품질 유지서 45-85% 절감 보고(FrugalGPT가 정준 레퍼런스), 에스컬레이션 비율이 라이브 비용 변수. [AI 게이트웨이와 모델 라우팅](03-ai-gateways-and-model-routing.md) 참고.
- **자체 호스팅 vs API 손익분기.** 프런티어 API 대비 손익분기가 월 수천만\~수억 토큰 보고지만, 로드 베어링 경고는 숨은 비용: 원시 GPU 대여가 실비의 30-40%뿐이라 약 2.5-3배 배수 적용, 엔지니어링 인건비가 인프라를 흔히 초과. 2026이 손익분기를 API 쪽으로 더 밀었다: GPU 대여 상승(Silicon Data B200 지수가 9월 진입 시 연초 대비 27.6%, 10/1 GPU시당 $5.86), API 가격 하락(GPT-6 Luna $0.10/$0.50가 라우팅·분류 티어의 자체 호스팅 오픈웨이트 서빙 대부분을 밑돔). 대부분 팀엔 풀스택 계산 시 관리형 API가 싸고, 자체 호스팅은 높고 예측 가능·잘 활용된 볼륨·데이터 레지던시 이유에 이긴다. [LLM 인프라](01-llm-infrastructure.md) 참고.
- **RAG vs 장문.** 검색이 쿼리당 장문 채우기보다 극적으로 싸다, 거대 프롬프트 대신 관련 청크 몇 개만 지불하니. 장문은 작고 정적인 문서셋, RAG는 크거나 자주 바뀌는 코퍼스·높은 쿼리 볼륨에 이김. [RAG 기초](../06-retrieval-systems/01-rag-fundamentals.md) 참고.
- **증류.** 소형 모델을 고정 평가서 프런티어의 정확도 몇 포인트 이내로 파인튜닝하면 토큰당 비용 5-40배 절감·고볼륨서 수주\~수개월 회수 보고; 좁고 고볼륨 작업에 이기고 개방형 롱테일엔 실패. 학생 모델이 살 곳 계획: OpenAI가 파인튜닝 플랫폼을 접고 있고 기존 고객도 2027-01-06부터 새 파인튜닝 작업 생성 불가라, 오픈 웨이트·다른 플랫폼이 안전한 집. [지식 증류](../03-training-and-adaptation/05-knowledge-distillation.md)와 [증류 사례 연구](https://github.com/ombharatiya/ai-system-design-guide/blob/main/16-case-studies/19-customer-distillation-pipeline.md)(영문) 참고.
- **출력·프롬프트 엔지니어링.** 간결 출력 계약·`max_tokens` 캡·구조화 출력·모델이 신뢰되면 few-shot 축소가 최소 품질 손실로 토큰 20-40% 절감 보고.
- **누가 추론을 지불하나.** 새 옵션 부상: Sign in with ChatGPT(2026-09-29 OpenAI DevDay 발표; 선정 파트너 제한 트라이얼)가 적격 Responses API 요청을 개발자 API 계정 대신 사용자 자신의 ChatGPT 플랜에서 돌리게 할 수 있음. 열리면 일부 추론 비용을 내 손익에서 옮기지만, 신원·AI 청구를 한 벤더에 묶는 대가.

## 비용 안티패턴

| 안티패턴 | 메커니즘 | 수정 |
|--------------|-----------|-----|
| 캐싱 없음 | 정적 시스템 프롬프트(입력 약 69%)를 매 호출 재지불 | 안정 접두사 + 제공자 접두사 캐싱 |
| 과대 모델 | 소형이 처리할 작업에 프런티어 | 라이트사이징·캐스케이드·라우팅 |
| 무제한 출력 | `max_tokens` 없음·장황 형식 | 캡·간결 출력 계약 |
| 기본 추론 켜짐 | 사소한 작업에 확장 thinking | 작업 복잡도로 thinking 게이팅 |
| 재시도 폭풍 | 일시 오류가 무제한 재시도 유발 | 제한 재시도·서킷 브레이커 |
| 폭주 에이전트 루프 | plan-act 루프가 종료 안 함; 도구 오류를 "재시도"로 읽음 | 루프 내 하드 스텝·토큰·재시도 상한 |
| 무제한 메모리 | 요약 없이 히스토리 누적 | 윈도잉·요약 |
| 장문 채우기 | 기본 검색으로 거대 컨텍스트 | 크거나 바뀌는 코퍼스엔 RAG |
| 귀속 없음 | 태그 없는 공유 지출 | 게이트웨이 토큰 프록시 + 태그 |
| 오프라인 작업에 실시간 | 평가·백필·라벨링에 동기 API | Batch API·Flex 티어 |
| 장문 임계 살짝 넘은 프롬프트 | OpenAI가 272K 입력 초과 시 전체 요청을 장문 요율로 | 아래로 트림·검색, 또는 평탄가 모델로 라우팅 |
| 전부에 레지던시 | 필요 없는 테넌트에도 모든 토큰 약 1.1배 | 게이트웨이서 테넌트별 지역 핀 |
| 프로모 가격 예산 | 인트로 요율 종료(Gemini Flash가 2027-01-01 2배) | 정가로 예측 |
| 지출 캡 429 재시도 | 캡이 월 1일까지 리셋 안 됨 | 오류 코드 분기; 페일오버·호출 |

보고된 실제 사건이 에이전트 루프 행을 구체화: 폭주 에이전트가 주말 하나에 수만 달러를 태운 뒤에야 알아챈 경우. 사후 알림이 아니라 루프 내 하드 상한이 방어; 관리형 런타임이 이제 네이티브로 제공(Claude Managed Agents 세션 예산).

## 면접 질문

### Q: 트래픽은 그대로인데 LLM 요금이 전월 대비 두 배가 됐다. 어떻게 찾고 고치나?

**좋은 답변:**
먼저 귀속: 모든 호출이 게이트웨이·프록시로 기능·팀·모델·경로 태그되지 않았으면 그게 첫 수정, 못 보는 걸 디버그 못 하니. 귀속이 있으면 토큰 지출 계층으로 분해해 흔한 범인을 봅니다: 캐시 적중률을 깬 프롬프트 변경(시스템 프롬프트가 입력 약 69%라 캐시 회귀가 거대), 단순 작업에 켜진 확장 thinking(출력 요율 과금·응답에 안 보임), 스텝 수가 슬그머니 오른 에이전트 루프, 무제한 출력·대화 히스토리, 재시도 폭풍. 그다음 플랫 트래픽이 숨기는 가격 구조 범인: 장문 임계 넘게 커진 프롬프트(272K 입력 초과 시 OpenAI가 전체 요청을 고요율로), Fast·레지던시 핀 티어로 드리프트한 트래픽, 캐시 읽기 요율이 다른 모델 스왑, 끝난 인트로 가격. 최고 ROI 수정은 거의 항상 프롬프트 캐싱 복원, 그다음 모델 라이트사이징·출력 캡. 오프라인 작업(평가·백필)을 Batch·Flex로 옮겨 절반, 기능별 예산·스파이크 알림으로 다음 두 배를 첫날 호출.

### Q: AI 제품이 SaaS보다 총마진이 나쁜 이유와, 엔지니어가 뭘 하나?

**좋은 답변:**
요청마다 가변 토큰 비용을 지녀 제로 한계비용 소프트웨어가 아니라 매출원가 비즈니스처럼 거동하기 때문; 보고 마진이 전형 SaaS보다 약 25-30포인트 아래. 엔지니어는 두 전선서 공략. 구조적으로: 정적 프롬프트 접두사 캐싱, 모델 라이트사이징·캐스케이드, 장문 채우기보다 RAG, 고볼륨 좁은 작업 증류, 오프라인 티어 배치. 운영적으로: 단위 경제학(대화당·해결 성과당 비용) 계측해 가격을 성과 기반으로 이동, 이는 해결당 비용을 알아야만 작동. 비용 레버는 재무만이 아니라 엔지니어링 책임.

### Q: 한 팀이 300K 토큰 컨텍스트 워크로드를 Claude Sonnet 5.5서 GPT-6 Sol로 옮기려 한다, 둘 다 정가 $2/$10이라. 뭘 확인하나?

**좋은 답변:**
정가가 같다는 건 가장 덜 유익한 사실. 먼저 장문 절벽: 272K 입력 토큰 초과서 OpenAI가 GPT-6 Sol 전체 요청을 $4/$15로 과금, Claude는 1M까지 평탄. 비캐시, 300K-in·2K-out 호출이 Sonnet 5.5서 약 $0.62($0.60 입력 + $0.02 출력), GPT-6 Sol서 약 $1.23라, "같은 가격" 이동이 컨텍스트를 272K 아래로 트림하거나 검색으로 대체 안 하면 호출당 비용을 대략 두 배. 둘째 캐싱: 둘 다 표준 길이서 $0.20 캐시 읽기지만 OpenAI 캐시 TTL이 30분 고정이라 워크로드 재사용 간격과 대조, 둘 다 1.25배 쓰기. 셋째 추론: Sonnet 5.5가 high effort 기본·thinking 완전 비활성 불가라, 보이는 출력이 아니라 총 과금 출력을 우리 트레이스서 비교. 넷째 배수: 레지던시(핀 시 양측 약 10%)·서비스 티어. 끝으로 품질·계약: 평가 스위트 실행, 강제 도구 선택 같은 요청 형태 차이 확인. 그다음 레이트 카드가 아니라 측정된 작업당 비용으로 결정.
