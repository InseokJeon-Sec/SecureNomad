# 10. AI 에이전트 · 툴 · MCP

지금까지의 LLM은 "질문하면 답하는" 수동적 존재였다. 여기에 **도구를 쥐여주고 스스로 일하게** 만든 것이 **AI 에이전트**다.

## 툴(함수 호출) — AI에게 손발을 달다

기본 LLM은 글만 생성한다. 계산·검색·파일 읽기 같은 **실제 행동은 못 한다.**
**툴(Tool) / 함수 호출(Function calling)** 은 LLM이 "지금은 계산기를 써야겠다"고 판단하면, 미리 연결된 **함수를 호출**하게 하는 기능이다.

```text
사용자: "오늘 서울 날씨 어때?"
   ▼
LLM 판단: "날씨 API를 호출해야겠다"  →  get_weather("서울") 호출
   ▼
결과(맑음, 20도)를 받아  →  "오늘 서울은 맑고 20도예요"로 답
```

- 덕분에 LLM이 **실시간 정보·외부 시스템**과 연결된다.
- 단, 무엇을 호출할지는 LLM이 **판단**하므로, 잘못된 호출·오남용 가능성도 있다(보안 고려 필요).

## 에이전트 — 스스로 계획하고 반복

**에이전트(Agent)** 는 목표를 주면 **① 계획 → ② 도구 사용 → ③ 결과 보고 판단 → ④ 반복**하며 스스로 일을 진행한다.

```text
목표: "경쟁사 3곳 가격을 표로 정리해줘"
  → 검색 도구로 각 사이트 조회 (반복)
  → 결과 취합
  → 표로 정리해서 보고
```

- 사람이 매 단계 지시하지 않아도 **여러 단계를 알아서** 밟는다.
- [ARTEX·PentestGPT](/security/ai-for-security/ai-tools/overview) 같은 "자동 침투테스트" 도구가 바로 보안 분야의 에이전트 사례다.

:::warning 에이전트의 보안 위험
스스로 도구를 쓰는 만큼, **잘못된 행동·과도한 권한·프롬프트 인젝션**에 취약하다. 권한을 최소화하고, 위험한 행동은 사람 확인을 거치게 하는 설계가 중요하다.
:::

## MCP — 도구 연결의 '표준 규약'

**MCP = Model Context Protocol.** AI와 외부 도구·데이터를 연결하는 **표준 방식**이다.

- 예전엔 도구마다 연결 방식이 제각각이었다.
- MCP는 "AI ↔ 도구" 사이의 **공통 규격**을 정해, 한 번 만든 도구(MCP 서버)를 여러 AI에서 재사용할 수 있게 한다.
- 비유: 제품마다 다르던 충전기를 **USB-C 표준**으로 통일한 것.

```text
[AI 앱] ──MCP── [파일 서버]
             └─ [DB 서버]
             └─ [사내 시스템]
```

## 정리

- **툴/함수 호출**: AI에게 행동할 손발을 달아줌
- **에이전트**: 스스로 계획·도구 사용·반복
- **MCP**: 도구를 연결하는 표준 규약
- 강력한 만큼 **권한·보안 설계**가 중요하다.
