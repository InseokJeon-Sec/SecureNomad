# 14. AI 보안 위협 지도

이 시리즈에서 우리는 편마다 AI 보안 위협을 하나씩 만났다 — 프롬프트 인젝션, 지식 포이즈닝, 과도한 권한, 숨긴 지시, 공급망까지. 문제는 이것들이 **흩어져 있어서** "우리 AI는 무엇을 점검해야 하나"를 한눈에 보기 어려웠다는 점이다. 이 문서는 그 위협들을 **한 장의 지도**로 묶고, 널리 쓰이는 표준 분류인 **OWASP LLM Top 10**으로 AI의 공격면을 정리한다.

## AI의 공격면 — 한 장으로

AI 애플리케이션은 **입력 → 모델 추론 → 지식·도구 → 출력·실제 행동**으로 이어진다. 그런데 이 **각 지점이 전부 공격면**이다.

| 단계 | 대표 위협 |
|---|---|
| **입력** | 프롬프트 인젝션 |
| **모델(가져오기)** | 공급망 위협(변조·악성 모델) |
| **지식·도구** | 지식 포이즈닝, 과도한 권한 |
| **출력·행동** | 출력 맹신, 무제한 소비 |

여기에 **전 구간을 가로지르는 위협**도 있다 — 민감정보 노출, 시스템 프롬프트 유출, 환각, 데이터·모델 오염. 핵심은 **특정 한 곳이 아니라 입력부터 출력까지 전 구간을 봐야 한다**는 것이다.

## OWASP LLM Top 10

이 공격면을 표준으로 정리한 것이 **OWASP LLM Top 10**이다. LLM 애플리케이션에서 가장 중요한 위협 열 가지를 분류해 둔 것으로, 보안 업계에서 널리 쓰인다.

| # | 항목 | 한 줄 |
|---|---|---|
| **LLM01** | 프롬프트 인젝션 | 입력으로 모델 지시를 덮어씀 |
| **LLM02** | 민감정보 노출 | 개인정보·비밀이 출력/학습으로 샘 |
| **LLM03** | 공급망 | 모델·도구·데이터의 변조·위조 |
| **LLM04** | 데이터·모델 포이즈닝 | 학습/지식에 악성 데이터 주입 |
| **LLM05** | 부적절한 출력 처리 | 모델 출력을 검증 없이 실행·표시 |
| **LLM06** | 과도한 권한(Excessive Agency) | 에이전트에 너무 넓은 권한 |
| **LLM07** | 시스템 프롬프트 유출 | 숨겨야 할 시스템 지침이 드러남 |
| **LLM08** | 벡터·임베딩 약점 | RAG 벡터 저장소의 오염·유출 |
| **LLM09** | 잘못된 정보 | 환각 등 틀린 출력을 신뢰 |
| **LLM10** | 무제한 소비 | 비용·자원 고갈(DoW/DoS) |

흥미로운 건, 이 **열 가지가 전부 이 시리즈에서 한 번씩 다룬 것들**이라는 점이다. 흩어져 있던 위협을 하나의 체크리스트로 모은 셈이다.

## 레이어별 책임

위협을 레이어로 나누면 **책임의 경계**가 분명해진다. AI 보안은 모델 하나가 아니라 **이 모든 레이어의 문제**다.

| 레이어 | 무엇을 책임지나 |
|---|---|
| **사람·프로세스** | 사용 정책·교육, 승인 게이트, 몰래 쓰는 **섀도 AI** 관리 |
| **애플리케이션** | 입력·출력 검증, 권한 최소화, 출력 맹신 금지 |
| **모델** | 출처·무결성, 안전성 평가, 시스템 프롬프트 보호 |
| **데이터** | 학습·RAG 데이터 품질, 벡터 저장소 접근통제 |
| **인프라** | 엔드포인트 인증·레이트리밋, 로깅·모니터링 |

## 전 구간 방어 5원칙

1. **신뢰 경계를 그어라** — 외부 입력·문서·도구 결과는 **데이터이지 명령이 아니다.**
2. **최소 권한** — 모델·에이전트·키에 꼭 필요한 만큼만. 되돌리기 어려운 행동은 사람 승인.
3. **출력을 검증하라** — 모델 출력을 그대로 실행·표시하지 말고 근거·형식·안전을 확인.
4. **공급망을 확인하라** — 모델·도구·데이터의 출처와 무결성을 검증.
5. **보고 기록하라** — 입력부터 위임·도구 호출·실행까지 연결해 로깅하고 지속 재평가.

## 무엇부터? — 우선순위

1. **무엇을 쓰는지부터 안다** — 조직 내 AI 사용 현황과 **섀도 AI** 파악.
2. **신뢰 경계부터 세운다** — 외부 입력을 명령으로 믿지 않게 설계.
3. **권한을 좁힌다** — 에이전트·키·데이터 접근 최소화 + 승인 게이트.
4. **평가와 레드팀** — 도입 전 성능·환각·안전 측정, 주기적 재점검.
5. **로깅과 모니터링** — 행동 기록을 **모델이 건드릴 수 없는 곳**에 남긴다.

> 완벽한 AI 보안은 없다. 중요한 건 **공격면을 알고 전 구간에 걸쳐 조금씩 좁혀 가는 것**이다.

## 시리즈 ↔ OWASP 매핑

이 시리즈를 따라왔다면 여러분은 이미 OWASP LLM Top 10을 한 번씩 경험한 셈이다.

| 편 | 주제 | 대응 OWASP |
|---|---|---|
| 3편 | 프롬프트 인젝션 | LLM01, LLM05 |
| 4편 | RAG | LLM08(벡터·임베딩), LLM04(포이즈닝) |
| 5편 | 에이전트·MCP | LLM06(과도한 권한), LLM03(공급망) |
| 6편 | 멀티모달 | LLM01(간접 인젝션), LLM02(민감정보) |
| 7편 | 파인튜닝 | LLM04(데이터 포이즌), LLM02(유출) |
| 8편 | 모델 평가 | LLM09(잘못된 정보) |
| 9편 | 로컬·오픈웨이트 | LLM03(공급망), LLM10(무제한 소비) |

> **오늘의 한 줄:** 새 능력을 붙일 때마다, 그 능력이 여는 **새 입력과 새 권한을 함께 통제**한다.
