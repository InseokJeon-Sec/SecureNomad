RAG의 검색을 떠받치는 두 요소가 **임베딩**과 **벡터 DB**다.

## 임베딩

**임베딩**은 단어·문장의 의미를 숫자 벡터로 변환한다.

```text
"고양이"  →  [0.21, -0.03, 0.88, ...]
"강아지"  →  [0.19, -0.01, 0.85, ...]   ← 고양이와 가까움
"자동차"  →  [-0.4, 0.7, 0.02, ...]     ← 둘과 멂
```

의미가 가까우면 벡터도 가깝다. 따라서 단어가 달라도 의미가 유사하면 검색된다(키워드가 아닌 **의미 기반 검색**). "불법 접근 차단 장비"로 검색해도 "방화벽" 문서를 찾는다.

## 벡터 DB

문서를 조각내 임베딩으로 변환·저장하고, 질문 벡터와 가장 가까운 조각을 빠르게 검색하는 데이터베이스다. Pinecone·Weaviate·Milvus·Chroma·pgvector 등이 있다.

```text
문서 → (임베딩) → 벡터 DB 저장        [사전 준비]
질문 → (임베딩) → 유사 조각 검색 → LLM에 근거 전달 → 답   [실행 시]
```

[07. RAG](./07-rag.md)의 검색 단계가 임베딩 + 벡터 DB로 이뤄진다. 유사도 계산·ANN 등 상세는 [RAG 내부 동작 심화](../deep-dive/rag-internals.md) 참고.
