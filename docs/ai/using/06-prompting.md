# 06. 프롬프트 기초

**프롬프트(Prompt)** 는 LLM에게 주는 입력(지시·질문·맥락) 전체다. AI를 잘 쓰는 건 결국 **프롬프트를 잘 쓰는 것**이다.

## 핵심 개념 3가지

| 개념 | 뜻 |
|---|---|
| **프롬프트** | 모델에게 주는 입력 전체 (지시 + 맥락 + 질문) |
| **컨텍스트 윈도** | 모델이 **한 번에 볼 수 있는 토큰 수**의 한계. 입력+출력 합산 |
| **토큰** | 처리 단위([03 참고](../foundations/03-how-llm-works.md)). 비용·한도의 기준 |

:::info 컨텍스트 윈도를 넘으면
대화가 길어져 한도를 넘으면, 모델은 **앞쪽 내용을 잊는다.** 긴 문서를 다룰 때는 요약하거나, 필요한 부분만 넣거나, [RAG](./07-rag.md)로 그때그때 찾아 넣는다.
:::

## 좋은 프롬프트의 원칙

| 원칙 | 나쁜 예 | 좋은 예 |
|---|---|---|
| **구체적으로** | "보안 알려줘" | "OWASP Top 10을 초급자용으로 항목당 2줄로 설명해줘" |
| **역할·맥락 부여** | "이거 검토해줘" | "너는 보안 검토자다. 아래 코드의 취약점을 심각도순으로 짚어줘" |
| **형식 지정** | "비교해줘" | "표로, 열은 도구·장점·단점" |
| **예시 제공(Few-shot)** | — | "이런 형식으로: [예시 1] [예시 2]" |
| **단계 유도** | "답만" | "차근차근 생각해서 근거와 함께" |

## 자주 쓰는 패턴

- **역할 지정**: "너는 ○○ 전문가다"
- **제약 걸기**: "300자 이내", "코드만", "존댓말로"
- **근거 요구**: "출처를 밝히고, 모르면 모른다고 해"
- **반복 개선**: 한 번에 완벽을 바라지 말고, 답을 보고 "더 짧게", "예시 추가"처럼 다듬기

## 보안 관점 주의

:::warning 프롬프트에 민감정보 넣지 않기
클라우드 LLM에 입력한 내용은 외부로 전송된다. **실제 계정·키·내부 코드·개인정보**를 그대로 넣지 말 것. 꼭 필요하면 익명화하거나 [로컬 LLM](../advanced/12-local-llm.md)을 쓴다.
:::
