사실관계는 [주간 보안 브리핑 W47](/news/2026/11/23/security-weekly-w47)에 적었다. 여기서는 그 두 건을 '에이전트 자동화 보안'의 눈으로 다시 읽는다.

## 사건 1 — agent-framework PyPI 탈취: '블래스트 반경'이 터진 현장

Microsoft의 공식 AI 에이전트 프레임워크 메타패키지에 악성 버전 두 개가 33분 간격으로 올라가 약 45분간 노출됐다. 핵심은 악성 코드가 `.pth` 시작 훅에 들어 있었다는 점이다. **패키지를 import하지 않아도, pip를 포함한 모든 파이썬 실행 때 돈다.** 그사이 환경 변수, `~/.azure`·`.git-credentials` 같은 자격증명 파일, IMDS를 통한 Azure 관리 ID 토큰, GitHub Actions OIDC 토큰까지 긁어 외부로 보냈다.

이걸 에이전트 자동화의 눈으로 보면 섬뜩하다. 에이전트는 결국 **토큰과 권한을 쥐고 무인으로 도는 프로세스**다. 그 실행 환경에 악성 의존성 하나가 들어오면, 에이전트가 쥔 git 토큰·클라우드 자격증명이 통째로 공격자에게 넘어간다. 내 문서에서 그린 **블래스트 반경**이 바로 이 그림이다. 더구나 `.pth` 훅은 에이전트 코드를 한 줄도 안 건드려도 **런타임이 뜨는 것만으로** 실행된다 — '과도한 에이전시'의 공급망 버전인 셈이다.

문서에 적었던 통제가 그대로 답이 된다. 의존성 **버전 고정**, 새 버전 공개 직후 일정 시간 설치를 막는 **cooldown**, 에이전트 실행 환경의 **시크릿 격리와 최소 권한 토큰**, 그리고 CI 러너에서 `webhook.site` 같은 범용 수집 서비스로 나가는 연결을 잡는 **이그레스 탐지**.

## 사건 2 — Meta Muse 장악: 간접 프롬프트 인젝션이 '실행 환경'까지

Meta의 개인 AI 에이전트 Muse가 **악성 웹페이지 하나를 여는 것만으로** 승인 창 없이 대화 기록과 저장된 기억을 외부로 보내고 바꿨다. 여기에 내장 브라우저 결함과 리눅스 커널 결함을 엮어, 사용자별 클라우드 머신 전체를 장악하고 자격증명 저장소와 감시 모듈까지 닿았다.

이건 내 문서의 **프롬프트 인젝션** 항목을 교과서처럼 밟는다. 외부 콘텐츠를 '명령'과 구분하지 못하는 순간(= 신뢰 경계가 없다) → 승인 없이 도구가 움직이고(과도한 에이전시) → 샌드박스 탈출로 **블래스트 반경이 실행 환경 전체로** 번졌다. 중요한 건 유출에서 끝나지 않고 **장악**까지 갔다는 점이다. 에이전트 브라우저는 일반 브라우저 수준의 격리가 필요하다는 걸 실제 사건이 증명했다.

## 두 사건을 하나의 지도에 얹으면

| 공격면 | 이번 주 사건 | 통제 |
|---|---|---|
| 외부 콘텐츠 수집 | Muse — 악성 페이지의 숨은 지시가 에이전트 장악 | 외부 콘텐츠는 '데이터로만', 승인 게이트 |
| 실행 환경·의존성 | agent-framework — 악성 패키지가 토큰 탈취 | 버전 고정·cooldown, 시크릿 격리 |
| 자율 행동 | 둘 다 — 승인 없이 유출·실행 | 도구 allow-list, 고위험은 사람 승인 |
| 사후 추적 | 둘 다 — 무엇이 나갔는지 | 전 구간 로깅·이그레스 탐지 |

## 그래서 — 내 '주간뉴스 자동화'에 대입하면

내가 만들려는 자동화에 두 공격면이 **그대로** 있다. 외부 뉴스를 긁어오는 단계는 사건 2(Muse)의 입구이고, 그 에이전트가 도는 실행 환경·의존성은 사건 1(agent-framework)의 입구다. 결국 통제도 같다 — 수집은 외부 콘텐츠 데이터화와 승인 게이트, 실행 환경은 의존성 고정과 토큰 최소화, 발행은 사람 승인, 전 구간은 로깅.

'에이전트를 **만드는** 법'이 아니라 '**안전하게** 만드는 법'이 핵심이라는 걸, 이번 주가 증명했다. 편리한 자동화는 동시에 공격 표면이다 — 만들기 전에 지도를 먼저 그려야 하는 이유다.
